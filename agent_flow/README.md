# Agent Flow

可视化编排 **TraeCode CLI（traecli）** 与 **WorkBuddy CLI（codebuddy）** 的工作流工具，类似 n8n：
拖拽加节点、连线组成 DAG、节点内编辑提示词、上游输出自动注入下游。

```
┌──────────┐      ┌──────────┐      ┌──────────┐
│ 写脚本    │ ──▶ │ 审查脚本  │ ──▶ │ 生成文档  │
│ codebuddy│      │ traecli  │      │ codebuddy│
└──────────┘      └──────────┘      └──────────┘
      └──────────────┴──── 输出经 {{nodeId.output}} 传递
```

## 核心能力

- **真 DAG**：分叉/汇合任意连，同层节点按「并发」上限并行（默认 1 = 串行，规避 CLI 限频）
- **数据传递**：`{{上游节点id.output}}` 注入提示词，另有 `{{input}}` 全局输入；可直接点 chip 插入
- **双 CLI 混用**：每个节点独立选择 traecli / codebuddy，同一条工作流里混搭
- **流式输出**：CLI 的 stdout/stderr 实时刷到节点卡片，不用干等
- **失败传播**：上游失败，下游自动 skipped（不会拿空输入白跑、白烧积分）
- **可中断**：运行中随时停止，会真正 kill 掉子进程
- **持久化**：自动存 localStorage，支持导出/导入 JSON 分享工作流

## 触发器

工具栏「⏱ 触发器」按钮打开管理面板，可添加 / 编辑 / 删除 / 开关。四种类型：

| 类型 | 说明 | 关键配置 |
|---|---|---|
| **手动触发** | 只在点击「立即执行」时跑一次 | 无 |
| **周期触发** | 每隔固定秒数自动跑（最小 10 秒） | 间隔秒数 |
| **定时触发** | 按 cron 表达式在指定时刻跑 | 五段 cron（分 时 日 月 周） |
| **监听触发** | 监听目录内文件变化后跑（带防抖） | 目录、后缀过滤、防抖毫秒、是否递归 |
| **调用触发** | 本地起 HTTP 服务，外部 curl / 脚本调用 URL 即触发 | 端口、路径、校验 Token、是否注入请求体 |

### cron 写法

```
*/5 * * * *     每 5 分钟
0 * * * *       每小时整点
0 9 * * 1-5     工作日早上 9 点
0 0 1 * *       每月 1 号零点
```

- 支持 `*` `*/n` `a` `a-b` `a-b/n` `a,b,c`，月份/星期可用英文名（`jan`、`mon`）
- 星期的 `0` 和 `7` 都表示周日
- 「日」和「周」同时被限制时取**并集**（标准 cron 规则），例如 `0 0 1 * 1` = 每月 1 号 **或** 每周一
- 面板里会实时显示中文描述和下次运行时间，写错了会红框提示

### 调用触发（webhook）

配置端口与路径后，桌面端会在 `127.0.0.1` 起一个极简 HTTP 服务：

```bash
curl -X POST http://127.0.0.1:8787/hooks/run \
  -H 'Content-Type: application/json' \
  -H 'X-Token: 你的token' \
  -d '{"branch":"main"}'
```

- Token 可留空（不校验），传 `X-Token` 头或 `Authorization: Bearer <token>` 均可
- 勾选「把请求体注入 {{input}}」后，下游节点可直接读 `{{input}}` 拿到请求体
- 同一端口可挂多个路径，各自对应不同触发器
- 面板里显示完整 URL 和可直接复制的 curl 示例

> ⚠️ 只监听 `127.0.0.1`，不对外网开放；但它**没有任何鉴权之外的防护**，
> 设了 Token 也建议只在本地可信环境使用。

### 三条保护机制

1. **防重入** —— 上一轮没跑完，新的触发直接跳过。周期再短也不会把 CLI 进程堆起来
2. **防抖** —— 监听触发默认 2000ms 合并窗口，一次保存 10 个文件只跑一次
3. **失败不停摆** —— 单次执行失败只记录结果，周期调度照常继续

> 开关（启用/停用）是总开关：关掉后连「立即执行」也不会跑，避免误触。

## 条件分支节点

工具栏「+ 条件」添加菱形决策节点。它**不调用 CLI、不消耗积分**，只做文本判定并决定走哪条路。

### 怎么用

1. 条件节点右侧每个出口对应一条规则（外加一个兜底出口）
2. 从指定出口拉线到下游节点 → 这条边就绑定了该分支
3. 运行时从上到下判定，**命中第一条即走对应分支**，其余分支的整条下游链路被跳过

### 判定方式

| 操作符 | 含义 | 需要比较值 |
|---|---|---|
| 包含 / 不包含 | 子串匹配 | ✓ |
| 等于 / 不等于 | 去首尾空白后比较 | ✓ |
| 开头是 | 前缀匹配 | ✓ |
| 正则匹配 | `new RegExp(value).test(text)` | ✓ |
| 非空 / 为空 | 去空白后是否有内容 | ✗ |
| 总是 | 恒真，用作保底分支 | ✗ |

判定来源可选：某个上游节点的输出 / 全局输入 / 全部上游输出拼接（默认）。

### 三个设计取舍

1. **非法正则不会炸掉流水线** —— 一条规则写了 `[` 只会跳过该规则并在界面报错，后续规则照常判定
2. **剪枝 ≠ 失败** —— 被跳过的分支不计入 failed，工作流仍算成功
3. **汇合节点走 OR 语义** —— 分支后再汇合，只要有一条路活着，汇合节点就执行

```
        ┌─ 含 "PROD" ─→ 部署生产
审查结果 ─┤
        └─ 兜底 ──────→ 仅发报告
```

## 四个新能力（本轮新增）

### 1. 多画布：新建 / 删除 / 改名 / 切换

窗口顶部是画布标签栏：

- **切换**：单击标签
- **改名**：双击标签，回车确认、Esc 取消。重名自动加 `(2)` `(3)` 后缀
- **删除**：标签上的 `×`。删中间项焦点落到后一项，删末项落到前一项，**至少保留一个画布**
- 每个画布有独立的节点、连线、触发器
- 内容变化 400ms 防抖后落盘；整个多画布状态存 localStorage，并做了损坏数据修复（缺字段补默认、重复 id 去重、失效指针回退）

### 2. 触发器变成画布节点

触发器不再藏在单独的面板里，而是画在画布上，一眼能看出"哪个触发器驱动哪条流水线"。

- 从左侧边栏拖入，或点工具栏「+ 触发器」
- 卡片上直接显示配置摘要（每 N 秒 / cron 表达式 / 监听目录 / webhook 端口路径）和**上次触发时间**
- 触发后状态回写到节点卡片
- 五种：手动、周期、定时、监听、调用（webhook）

### 3. 左侧节点库（可拖拽）

四类节点：任务（traecli / codebuddy）、触发器（五种）、条件分支、并发控制。
拖到画布任意位置，或点击直接添加。

### 4. 并发节点：可按条件决定并发度

三种模式：

| 模式 | 行为 |
|---|---|
| 固定并发数 | 下游统一按这个数并发（1~16） |
| 按条件决定 | 对上游输出做包含/正则判定，**命中第一条即用其并发数** |
| 不限制 | 全部并行（受全局上限 16 约束） |

作用于它的**所有下游**，直到遇到下一个并发节点。多入边时取继承值的最小值（保守）。

典型用法：耗时的 AI 任务设 1~2 避免撞限频，轻量的文件处理设大并发。

```
[并发节点: 输出含 "PROD" → 并发 8，否则 1]
        ↓
   ┌────┴────┐
 任务A    任务B     ← 按解析出的并发度跑
```

并发节点不调用 CLI、不消耗积分。

## 删除节点与连线

选中后按 **Delete**（也支持 Backspace）即可删除，连线同理。工具栏另有「删除」「↩ 撤销」按钮。

配套行为：

- **删除节点会连带删掉与它相连的所有边**，不留悬空连线
- **运行中禁止删除**，避免执行器引用到已消失的节点
- **撤销**：`Ctrl/Cmd + Z` 或点「↩ 撤销」，恢复最近一次删除（节点、连线、选中态一并还原）
- **悬空引用提示**：如果下游节点的提示词还在引用 `{{被删节点.output}}`，删除后底部会给出警告。
  因为运行时它会把变量原样传给 CLI，属于静默错误，不提示很难发现

> 撤销只保留最近一次。这是刻意的取舍——单次误删是绝大多数场景，
> 完整 undo 栈会引入一整套状态管理复杂度。

## 跑起来

### 1. 前置条件

| 依赖 | 说明 |
|---|---|
| Node.js 18+ | 前端构建 |
| Rust 1.77.2+ | Tauri 2 后端，`rustup` 装 |
| 系统图形库 | Linux 需 `libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev librsvg2-dev`；mac/Windows 无需额外装 |
| traecli / codebuddy | 需已安装且在 PATH 中 |

Linux（Debian/Ubuntu）装系统依赖：
```bash
sudo apt install -y libwebkit2gtk-4.1-dev libgtk-3-dev \
  libayatana-appindicator3-dev librsvg2-dev
```

### 2. 启动

```bash
npm install
npm run tauri dev      # 开发模式，首次编译 Rust 较慢
```

打包成安装包：
```bash
npm run tauri build
```

只想调试画布不启动 Rust（会用模拟输出代替真实 CLI）：
```bash
npm run dev            # 打开 http://localhost:1420
```

## 目录结构

```
src/
├── engine/            纯逻辑，无 UI 依赖，可单独测试
│   ├── topo.ts        Kahn 分层拓扑排序 + 环检测
│   ├── template.ts    {{变量}} 渲染
│   ├── cron.ts        cron 解析、校验、下次运行时刻计算
│   ├── canvasOps.ts   画布删除：连带边、选中态、悬空引用、撤销快照
│   └── condition.ts   条件规则求值（非法正则容错）
│   └── triggers.ts    触发器调度器：防重入、防抖、失败容错、webhook
│   └── runner.ts      DAG 调度：分层并发、失败传播、流式转发
├── lib/tauri.ts       前端↔Rust 桥接（含浏览器降级）
├── components/        画布节点卡片、属性面板
└── App.tsx            画布 + 调度接线

src-tauri/src/lib.rs   Rust 侧：spawn CLI、流式 emit、kill 进程、目录监听、webhook HTTP 服务
tests/                 单元测试（npm i -D tsx && npm test）
```

## CLI 参数是怎么拼的

`src-tauri/src/lib.rs` 的 `build_args()`：

| CLI | 命令 |
|---|---|
| traecli | `traecli exec "<prompt>" [-m <model>] [-y]` |
| codebuddy | `codebuddy -p "<prompt>" --output-format text [--model <m>] [-y]` |

> 如果你的 traecli 版本要求选项放在 `exec` **之前**（如 `traecli -m x exec "..."`），
> 改 `build_args()` 里的 push 顺序即可，一处改动全生效。

## 权限配置

`src-tauri/capabilities/default.json` 已声明 traecli / codebuddy / cbc 的 spawn 与 execute 权限。
如果你把 CLI 装在非标准路径、或在界面里改成绝对路径，需要往这个文件补一条：

```json
{ "name": "mycli", "cmd": "/abs/path/to/cli", "args": true }
```

## 已知限制

- 节点输出会完整保留在内存里，超长输出（几百 KB）建议手动清空再跑下一轮
- 并发数调高时注意 CLI 侧的限频：codebuddy 触限报 6004，是**滚动窗口**而非自然日刷新
- 目前每次运行都会新建进程，不做会话复用；需要多轮对话式任务请在单个节点内描述完整
- **文件监听与调用触发只在桌面端生效**（依赖 Rust 的 notify 与本地 HTTP 服务）。
  `npm run dev` 的浏览器模式下这两类触发器会置灰提示
- webhook 服务只绑 `127.0.0.1`，端口被占用时会在触发器面板报错，换一个端口即可
- 条件分支的连线必须从条件节点右侧**指定出口**拉出，否则视为无条件边（始终执行）
- 周期触发的最小间隔是 10 秒，且受防重入约束：若一轮工作流跑 5 分钟，间隔设 1 分钟也不会并发
- 触发器配置存在 localStorage，换浏览器/清缓存会丢失，重要配置请用「导出」备份

## 测试

核心逻辑（DAG 调度、模板渲染、cron 解析、触发器调度）都在 `tests/` 下，共 30 个用例：

```bash
npm i -D tsx
npm test
```

覆盖的关键场景：

- DAG：线性链、分叉汇合、环检测、悬空边、祖先收集
- 调度：上游失败传播到孙节点（不会拿空输入白跑）、并发上限、模板变量渲染
- cron：步进/范围/列表、周日归一化、越界校验、**跨月跨年推进**、无解表达式返回 null 而非死循环
- 触发器：间隔到期判定、停用后不触发、**防重入**、cron 到点触发与自动重算、表达式变更不补触发、
  监听防抖合并、后缀过滤、失败后继续调度、移除后清理定时器、webhook 调用与停用拦截
- 条件：各操作符行为、规则优先级、兜底分支、非法正则容错、判定来源（上游/input/拼接）
- 删除：节点连带删边、多节点/边混合删除、悬空引用检测、选中态修正、快照深拷贝、文案
- 并发：并发数钳制（含 NaN/Infinity 保守归 1）、三种模式、按条件命中顺序、
  非法正则跳过而不断流、Infinity 收敛到任务数
- 多画布：默认命名避重、改名去重后缀、删除后焦点落点、持久化损坏修复与 id 去重
- 分支：命中分支执行 + 另一分支被裁、剪枝传播到孙节点、汇合节点 OR 语义、
  无条件边不受影响、条件节点不调 CLI、失败仍算失败（区别于剪枝）

另外 `npm run check` 会静态校验所有相对导入路径与关键导出，
在没有 tsc 的环境里可以快速发现"改了文件名忘了改引用"。
