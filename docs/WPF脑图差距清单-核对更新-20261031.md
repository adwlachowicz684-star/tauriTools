## 四、20 项误判的成因（记下来以免重犯）

| 成因 | 项 | 说明 |
|---|---|---|
| 原就实现，清单判"完全缺失" | A12 A25 A26 A27 A28 A45 A46 A63 B13 | 9 项，功能本来就在 |
| 内核本来就提供 | B2 B3 | `ClipboardModule` 有 `copy/cut/paste`；`DragTree` 取 `getSelectedAncestors()` 天然支持多选 |
| WPF 原版根本没有 | A34 A35 A36 A37 A41 B29 | 6 项，全仓搜 `Print` 零命中 |
| WPF 原版没有此功能 | B14 B15 | `summary` 命中全是 C# `/// <summary>` 文档注释；`relation` 在脑图代码零命中 |
| Web 端天然成立 | B7 | 程序化赋值不触发 `change` 事件，WPF 的 `_syncingStyle` 抑制在 Web 不需要 |

**共同教训**：只搜字符串字面量会漏判——min.js 里命令写作
`commands:{copy:i,cut:j,paste:k}`，是标识符不是字符串，搜 `"copy"` 零命中。
凡清单标注「未定位到确切行号」的，都必须先核实再动手。

## 五、4 项建议不做

| 编号 | 功能 | 为什么不做 |
|---|---|---|
| A68 | 安装/卸载脑图组件 | WPF 的「脑图组件」是可插拔模块，装了才有面板。Web 是单页面板，**没有"安装"这个概念**，硬做只能是个假开关 |
| A69 | 组件未启用占位 | 依附 A68 存在；若要保留价值，可降级为「面板显隐开关」 |
| A10 | ico 多尺寸转换 | 已用 **SVG 图标**替代 `.ico`，天然无损缩放。图标库内置图标全是手写 SVG path |
| B19 | ico 最大帧转 PNG | 同上，转换逻辑不适用 |

## 六、仍未验证的部分（与本次核对无关，属遗留风险）

收口清单第六节已记录，本次未重复验证，一并保留提醒：

1. **Rust 侧三个命令从未 `cargo build` 过**（沙盒无 cargo）：`mm_print`、
   `mm_svg_to_pdf`、`mm_open_devtools`。其中 `mm_svg_to_pdf` 是**默认 PDF 通道**，
   编译不过等于导出功能挂掉；且新增了 `svg2pdf` 依赖（约 8–13MB）。
2. **jsdom 测不到的真实环境行为**：非 100% 缩放下双击编辑节点、页签拖拽手感、
   打印预览深色主题背景、A71 诊断窗口能否收到 iframe 报错、拖 3 个文件到同一节点。
