### 五、反向清单：当前有而原版没有（**勿因对齐原版而删**）

复刻时最容易犯的错——照着原版把新版做得更好的地方删掉。以下 12 项是**当前版独有增强**：

| # | 增强 | 原版为何没有 |
|---|---|---|
| #489 | MCP **非阻塞 accept + 条件变量唤醒** | 原版 stdio，无需释放端口 |
| #490 | 连接数上限 `MAX_CONNS`，过载直接关连接 | 原版 stdio 无此场景 |
| — | 监控用 `AtomicU64` **代次号** | 解决"stop 后立即 start"的双线程竞态，原版无此场景 |
| #406 | 本地 scaffold **同名自动避让**（永不覆盖） | ✅ 原版也有（D5） |
| #485 | JSON-RPC id 按原始类型回传 | ✅ 原版也有 |
| — | `backup_dir` 字段（备份根） | 原版把备份目录分在项目/项目组字段里 |
| — | `watch_interval_secs` 可调轮询间隔 | 原版用 FileSystemWatcher，无间隔概念 |
| — | `folder_icons` 统一图标映射 | 原版 `folderLock`+`guiFolderIcons` 两套 |
| — | iframe 沙箱下**轮询 + 前端拉取**代替 emit | 原版无 iframe 限制，`app.emit` 直接可达 |
| — | MCP 走 **HTTP over TCP**（非 stdio） | **架构选择不同**，见下 |

> **注意 #479 的架构差异**：原版 MCP 是 stdio JSON-RPC（`--mcp` 不开窗口），
> 当前是 HTTP over TCP（绑定端口，常驻 GUI 内）。**不是缺功能，是架构不同**，
> 但后果很实际：原版 README 的 `.mcp.json` 配置方式在当前版 **100% 不可用**。

| | 原版 | 当前 |

### 本轮方法论教训 ⭐

**前几轮一直"按行数倒序"打开文件，导致所有 100-140 行的文件从未被打开过。**

这是一个系统性盲区：
- 大文件（>1000 行）→ 第一轮就开了
- 中等文件（100-140 行）→ **从来没开过**
- 小文件（<100 行）→ 偶尔在 grep 时扫到

本轮专攻这一档，**+74 项，是十轮以来第二高**（仅次于第四轮的 +90）。

**修正后的做法**：不要只按行数倒序。要么**按行数分区间各取一批**，要么在后期专门补一轮"中等文件"。

### 本轮最重的一项：504 官方 API 优先

原版注释明确写：`SHGetSetFolderCustomSettings(FCSM_ICONFILE, FCS_FORCEWRITE)`
"由系统自行维护 desktop.ini 与外壳解析缓存，**二次换图标即时生效的关键**"。

当前只直写 desktop.ini。这意味着：
- 即使补上 SHChangeNotify（#301）
- 即使修了空格引号（#304）和 UTF-16 编码（#303）
- **换第二次图标仍可能不刷新**——因为外壳缓存由系统 API 维护，直写绕过了它

**图标相关（#301-308、#504-524）共 24 项，建议作为一个整体批次处理**，而不是零散修。

### 本轮另一收获：触发器优先级

XAML 里三条注释揭示了原版踩过的 CSS/WPF 通用坑：
```
// BorderBrush 放 Style Setter 而非本地值，否则本地值优先级高于触发器，IsGrayed 无法覆盖为红框
// 文件夹丢失：悬浮/按下时也保持红色边框（模板内触发器优先级高于 Style.Triggers，需在此覆盖）
// 自定义标签色：必须排在上方默认触发器之后——同属性多触发器命中时以后者为准
```
**这三条在 CSS 里完全对应**：`!important` / 选择器特异性 / 规则顺序。
当前 CSS 若没注意，会出现"缺失卡片 hover 时红框消失"（#233）这类问题。
