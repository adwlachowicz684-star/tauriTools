## 一、校验脚本（跨插件）

### `nexus-panel/cross-end-check.mjs`

**作用**：校验前后端契约不漂移。四类检查：

| # | 抓什么 |
|---|---|
| C1 | 命令定义了没注册 / 注册了没定义 / 前端调了不存在的 |
| C2 | 前端参数名 ≠ Rust 参数名 |
| C3 | Rust 非 `Option` 的参数前端没传 |
| C4 | `model.rs` 字段 ≠ `types.ts` 字段 |

**当前状态**：命令 47 · 注册 47 · 调用 48（含 1 个外壳命令），全绿。

**用法**：
```bash
cd nexus-panel && node cross-end-check.mjs            # 打印
node cross-end-check.mjs --strict                     # 有错退出码 1（CI）
```

**已接入 CI**，放在最前面（只需 node，不用 cargo/npm install，几十毫秒快速失败）。

**⚠️ 为什么必须跑**：config 是**整份覆盖写回**的，TS 少一个字段，Rust 不认识就丢弃。
之前 `FpxConfig` 漏 `chainActions` 就是这么丢的用户数据。

**⚠️ 改这个脚本后必须做故障注入** —— 第一次跑就"全绿"要怀疑脚本是死的。
四类错误各造一个，确认都能抓到。

## 二、颜色工具 `plugins/project-group/utils/color.ts`

| 导出 | 用途 |
|---|---|
| `normalizeHex` | 归一化为 `#RRGGBB`，支持三位简写，非法返回 null |
| `hexToRgb` / `rgbToHex` | 互转 |
| `shade(hex, amount)` | 派生色（>0 变亮，<0 变暗） |
| `luminance` / `isDark` | 感知亮度（BT.601 权重），决定叠黑字还是白字 |

**来源**：从 `ColorPicker.tsx` 的私有副本收敛而来。
**使用者**：`ColorPicker`、卡片标签色（`CardGrid`）。

**⚠️ 注意**：
- `shade` 用"离白/离黑各有余量"算法，不是简单乘系数——后者对已经很亮/很暗的颜色几乎没效果
- `luminance` 用 BT.601 权重（0.299/0.587/0.114），**不能用简单平均**：
  人眼对绿色最敏感，平均会把亮蓝（`#0091FF`）误判为暗色，白字上去就糊了

## 三、UI 基础件 `plugins/project-group/components/ui.tsx`

| 导出 | 说明 |
|---|---|
| `Modal` | 居中弹窗；`guardClose` 有未保存改动时点遮罩先确认 |
| `ConfirmDialog` | 确认框；**回车与"确定"按钮走同一路径**（否则弹窗不消失，重复执行） |
| `ContextMenu` | 右键菜单，**渲染到 `MenuLayerContext` 指定的图层** |
| `MenuLayerContext` | 菜单图层 |

### ⚠️ 菜单层级（踩过的坑）

外壳 `neumorphism.css` 对 `.p-card` 等元素加了 `backdrop-filter`。
**这个属性会同时做两件事**：

1. 该元素成为**层叠上下文** —— 里面 `z-index:1000` 的菜单不参与全局比较
2. 该元素成为 `fixed` 后代的**包含块** —— 菜单按卡片定位，而传的是视口坐标，整体偏移

**现象**：菜单被相邻卡片盖住 + 位置偏到右边一栏。

**解法**：菜单统一 portal 到 `.fpx-menu-layer`（`position: relative; z-index: 20`）。
用 `relative` 而非 `fixed`/`transform`——后者会产生 fixed 包含块，把定位带偏。
`z-index: 20` 刻意卡在中间：高于三栏（`auto`），低于弹窗遮罩（`.mask` 900）。

**⚠️ 同类隐患**：`.dialog` 也在那个选择器列表里 → **嵌套弹窗**的遮罩只盖住父弹窗那块。
`IconPickDialog`、`BackupDialog` 是嵌套的；`CreateDialog` 用 fragment 把 `DirDialog` 放外面是对的。

## 四、可复用业务件

| 组件 | 复用注意 |
|---|---|
| `SideRail` | 左操作栏；`hotkey` 用 `mod` 代指，内部按平台替换 |
| `TabBar` | 页签条；**两种拖拽 MIME 分开**：`x-fpx-card`（移动卡片）/ `x-fpx-tab`（重排页签） |
| `CardGrid` | 卡片网格；拖拽载荷来自 dataTransfer（任意文本），**必须结构校验** |
| `LinkPickDialog` | 建链选名；"将换绑"提示对应后端 `create_one` 的**先删再建**语义 |
| `ContentPanel` | 内容浏览；目录直达**不拼 `root/agents`**（后端兼容单复数，拼错就打不开），改为从条目反推基目录 |

### 拖拽载荷校验（通用规则）

`dataTransfer` 的内容可以是**任意文本**（从别的应用拖进来或人为伪造）：
- 直接 `JSON.parse` 会抛异常中断处理
- 更隐蔽的是解析成功但结构不对，后续字段为 undefined 造成**静默错乱**

所以既要兜异常，也要做结构校验（`parseDragPayload` / `parseTabDrag`）。

## 五、样式约定

| 类 | 说明 |
|---|---|
| `.fpx-col-head` | 三栏统一头部（`min-height:30px`、`margin-bottom:12px`、`nowrap`） |
| `.fpx-menu-layer` | 菜单图层，见上 |
| `.fpx-tab.tab-over` | 页签重排落点（左内描边）vs `.drop`（卡片拖入，整卡高亮）——**刻意区分** |
| `.fpx-card.missing` | 红框，**优先级高于 hover** |

**⚠️ 三栏上边缘对齐**：外壳有 `.p-card + .p-card { margin-top: 16px }` 规则，
三栏都是 `.p-card` → 第 2、3 栏被整体推低 16px。**已清零，别再加回来。**
