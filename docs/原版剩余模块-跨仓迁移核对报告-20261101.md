## 三、真实差距（Windows 专属，4 项）

| # | 原版 | 说明 | 建议 |
|---|---|---|---|
| D1 | `TaskbarPinner`(135 行) | 改写 exe 图标后，任务栏固定条目的图标不会自动更新；原版靠"删除固定 .lnk → 广播 `SHChangeNotify` → 原样重建"强制刷新（等价于 unpin→repin），且重建失败会还原 | **不迁移**。依赖 Windows 任务栏固定目录与 Shell 通知，跨平台无对应物 |
| D2 | `AppIconService.UpdateExeIcon` | 直接改写 exe 的 PE 资源换图标（含 PE 校验和重算 `PeCheckSum`），**永久生效**（重启后仍是新图标） | 见 3.1 |
| D3 | `HideTaskbarInFullscreen` | 全屏/最大化时铺满屏幕盖住 Windows 任务栏（配置字段，默认保留） | **不迁移**。本版窗口由外壳托管，任务栏行为属宿主能力 |
| D4 | `AcrylicService`(71 行) | 亚克力（毛玻璃）背景效果 | **不迁移**。Windows 专属视觉，本版走 CSS 主题体系 |

### 3.1 唯一值得单独说的一处：软件图标**持久性**比原版弱

- 原版：`UpdateExeIcon` 改 **exe 文件本身** → 换图标**永久生效**（窗口标题栏 / 任务栏 / 托盘 / 资源管理器全都变，重启后仍是新的）
- 本版：`SettingsDialog.tsx:325` 注释自己写着 `已把「${name}」设为软件图标（**重启后恢复默认**）` → 只是**窗口级**，重启即回退

也就是说：本版**有这个功能、也更好用**（两步确认、拖放、粘贴），但**效果不持久**。

> 要不要补，属于取舍：改自身可执行文件在 macOS/Linux 上不适用（且有签名/权限问题），而本版是跨平台的。
> **建议**：若确定不补，把这条写进本节——否则后人重挖一次会再纠结一遍。

## 五、看着像缺口、核实后确认无需处理（8 项）

本轮先做了关键词扫描，它对**下面每一项的判断都是错的**，方向还各不相同：

| 项 | 关键词扫描的结论 | 实际 |
|---|---|---|
| Agent 连锁 | `agent_chain` 0 命中 → "缺失" | 已迁移，本版叫 `chain-builtins` + `placeholders` |
| 文件夹监视 | `folder_watch` 0 命中 → "缺失" | 已迁移，本版叫 `watch.rs`（我搜的关键词本身就错了） |
| 软件图标 | `app_icon` / `customAppIcon` 在 `js/`、`src-tauri/src`、`settings`、`home` 下 0 命中 → "缺失" | 已迁移，在 `project-group/components/SettingsDialog.tsx`，中文叫"软件图标" |
| 数据自检 | `selfcheck` 只 3 命中 → "可疑" | 已迁移为 CLI 子命令 |
| 备份 | `backup` 51 命中 → "像是有" | 确实是，但 51 命中里绝大多数是**脑图备份**与测试；真正的一键备份是 `fpx/backup.rs`——**命中数多反而藏住了它** |
| 任务栏 | `taskbar` 6 命中 → "像是有" | 只有 D1/D3 两处提及，**功能确实没有**（真缺口） |
| 侧边栏常驻 | `sidebarPersistent` 原版有、本版无 → "缺失" | 原版自己的浮层形态已改，见 `分配项目组-跨仓迁移差距审计.md` 排除项 |

**教训（值得记住）**：关键词扫描会**同时**产生"假缺失"（命名不同）和"假对齐"（命中数来自无关模块）。
本轮的判断没有一条是靠关键词下的——每条都回到了两侧代码读实现，或读了本版注释里对原版的对照说明。
