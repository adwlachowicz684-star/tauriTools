## 二、发现的问题（按风险排序）

### P0 · WPF dist 内的 1.6G 备份数据是唯一副本

```
分配项目组迁移/dist/backkup_项目备份/     1.2G   ← 项目备份（真实用户数据）
分配项目组迁移/dist/backkup_项目组备份/   382M   ← 项目组备份（真实用户数据）
```

WPF 工具的数据目录就在自己的 dist 里（新版数据在 `%APPDATA%/com.nexus.panel/`）。
这意味着：**动 WPF 目录 = 动这 1.6G 数据的唯一存放点**。新版 project-group 数据目录
目前只有 8K config.json，尚无对等备份数据。**在任何目录整理动作之前，必须先全量备份这 1.6G。**

### P1 · WPF 三份目录并存，命名与性质错位

| 目录 | 实际内容 | 问题 |
|---|---|---|
| `分配项目组迁移/` | 正本：src（迁移参照真源，多份文档按行号引用）+ dist（exe + 1.6G 数据） | 参照与数据混装 |
| `- 副本 20261021-024626/` | 14M 全量快照（无数据） | 与正本 src 重复；一次性快照无说明 |
| `- 副本/` | 项目工作区快照（agents/mcp.json/memory） | **与工具无关**，放在工具开发目录纯属误放 |

### P1 · dupview Python 遗留是孤儿

`dupview_web_legacy/`（dupview_server.py 1193 行 + dupview_addroot.py 982 行）在
tauriTools 全库 grep 零引用——Rust `dupview` 模块 + 插件已完整取代。留着只会让下一个人
困惑「该跑 Python 还是用插件」。

### P2 · 文档三处散落 + 一个放错位置的测试

- `tauriTools/docs/`（12 个）+ `nexus-panel/docs/`（3 个）+ `tauriTools/` 根（脑图三件 +
  打印PDF对比 + WPF脑图差距清单-附件/）——**三个位置**，无规矩说明什么文档该放哪。
- `tauriTools/nexus-panel__controls-test.mjs`（132K）——nexus-panel 的测试却躺在
  tauriTools 根，与其余 40+ 个 `*-test.mjs` 不同址。

### P2 · 磁盘占用失真，误导空间判断

center_console 16G 里 13G 是 Rust `target/`（构建产物）。skill-tree 800M 里 630M 是
`pending/`（其自有审查产物）。看目录大小会严重误判「代码资产」实际只有几十 MB 量级。

## 三、整合方案（四层，按风险从低到高）

### 第 1 层：零风险归位（随时可做）

| 动作 | 内容 |
|---|---|
| 测试归位 | `tauriTools/nexus-panel__controls-test.mjs` → `nexus-panel/`（与其他测试同址） |
| 脑图档案入册 | 脑图三件 + `WPF脑图差距清单-附件/` + `打印与PDF方案对比.md` → `tauriTools/docs/`（历史档案区，卷首注明「迁移已收口」） |
| 误放物迁出 | `分配项目组迁移 - 副本/`（项目工作区快照）→ 移出 `工具开发/`，去它该去的地方 |
| 定文档规矩 | `工具开发/` 根新增 README.md：一页说明各目录职责/归属/现役状态（见第五节草案） |

### 第 2 层：孤儿归档（低风险）

- `dupview_web_legacy/` → 整体入 `tauriTools/docs/` 旁新设的 `_archive/`（或压缩后留存），
  并在 nexus-panel README 的 dupview 节注明「Python 旧实现已归档，现役为 Rust 模块 + 插件」。
- 观察项：`%APPDATA%/com.nexus.panel/dupview` 已 2.4G——确认新版 dupview 是否有
  扫描数据清理/上限机制，没有则列入待办（这比 Python 归档更影响日常使用）。

### 第 3 层：WPF 遗产整合（**需先备份，需单独确认**）

前置：`robocopy /E` 全量备份 `分配项目组迁移/`（含 1.6G 数据）到备份盘，校验通过再动。

| 动作 | 内容 |
|---|---|
| src 归档为参照 | `分配项目组迁移/src/` → `tauriTools/_wpf-ref/src/`（多份文档按 `wpf-ref/src` 引用它，本就该是这个位置；与 `docs/` 平级） |
| 快照去重 | `- 副本 20261021-024626/` 与正本 src diff，无差异则删除（已有全量备份兜底） |
| 数据单列 | dist 的 1.6G 备份数据 → 移入 `分配项目组迁移/_data/` 或整体搬去备份盘，与「代码/exe」分离 |
| exe 缓退 | exe 暂留，待系统图标 #5-12 本地验收通过后，WPF 正式退役（退役 = 移入 `_archive/`，不是删除） |

### 第 4 层：明确不做

- **不合并 skill-tree**：独立生态（自有 AGENTS.md / SKILL-MAP.yaml / rules），与 center_console
  无代码关系，并列放在 `工具开发/` 即可，其 630M pending 归其主自决。
- **不动 Rust/插件代码**：已是一套，无需「统一实现」。
- **不删 WPF src**：迁移参照真源，多份文档按行号引用。
- **不清理 target/**：13G 构建产物，`cargo clean` 一次可回收但重建耗时——列为「空间紧张时再做」。
