## 三、后端需要新增的命令

### 3.1 `fpx_extract_pe_icons(path, out_dir) -> Vec<String>`

从**任意 PE 文件**（`.dll` / `.exe`）提取图标，写入数据目录 `icons/`，返回文件列表。

统一用它覆盖 #5（系统 DLL）和 #6（选 EXE）：

- 系统图标页签：`path` 传 `C:\Windows\System32\SHELL32.dll` 等
- 选文件：`path` 传用户选的 exe/dll

**关键：必须先做能力探测**。加一条：

### 3.2 `fpx_pe_icon_support() -> bool`

返回当前环境能否提取 PE 图标。前端据此**自动禁用**「系统图标」页签并说明原因。

为什么需要它：开发沙箱是 Linux，对 Windows PE 的资源目录解析**很可能不可用**
（表现：能探测到 group icon 资源条目，但完整提取返回"PE 文件不包含任何图标目录"）。
若不做探测，到了不支持的环境上会直接报错；而用户在**真正的 Windows** 上大概率是好的。
有了它，两边都不会难看。

### 3.3 `fpx_import_clipboard_image(data_base64) -> String`

接收前端从剪贴板拿到的图片（PNG data URI 的 base64 部分），转成多尺寸 `.ico`。

## 四、技术要点与已知坑

### 4.1 剪贴板 ICO 必须多尺寸（#7）

只生成单个尺寸的 `.ico`，资源管理器在**部分视图**（尤其"大图标"及以上）会显示模糊。
图标文件里应同时包含：

```
256 · 128 · 64 · 48 · 32 · 16
```

按原图尺寸降序重采样；原图小于某尺寸时跳过该档，不要放大（放大只会更糊）。

### 4.2 resvg 的 `Pixmap::from` 要 `Vec<u8>`，不是切片

```rust
// ❌ 编译失败
Pixmap::from(&bytes)
// ✅
Pixmap::from(bytes.into_owned())
```

这条只有 `cargo build` 能发现，写代码时容易漏。

### 4.3 提取失败的兜底路径

当 DLL 提取不可用时（`fpx_pe_icon_support()` 返回 false），前端**不要只显示报错**，
应提示用户：可直接选一个 exe/dll 文件，后端用同一套提取逻辑处理。
这条路径不依赖系统 DLL 的位置，覆盖面更广。

### 4.4 图标引用形式

后端 `fpx_set_icon` 接受的 `icon_ref` 是：

```
"<ico 路径>"          单个 ico 文件
"<dll 路径>|<索引>"    DLL 里的第 N 个图标
```

系统图标页签选中后，走的是"提取落盘成 ico 再引用"还是"直接引用 `dll|index`"，
需要定下来。**推荐前者**（落盘成 ico）：后者依赖目标 DLL 一直存在，
系统更新后 DLL 里的图标索引可能变化，引用就断了。

### 4.5 非模态常驻（#9）

原版色盘 / 图标面板都不关，去主面板点另一张卡片，面板标题跟着变、应用到新卡片。
这需要外壳支持"面板保持存活 + 接收目标变更通知"，**先确认外壳能力再动工**。
