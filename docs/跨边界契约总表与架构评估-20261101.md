## 一、结论先行

**契约本身是清楚的，问题不在"没设计"，而在"同一份契约常常有两处实现，靠测试钉住它们不漂移"。**

三个量化信号：

| 信号 | 数字 | 说明 |
|---|---|---|
| 宿主核心 `js/` | 40 文件 / 18.2k 行 | 被测的那一层 |
| 根目录守卫 `*-test.mjs` | 114 文件 / **36.6k 行** | **是宿主核心的 2 倍** |
| 测试里"两份/两套/两侧/三份/同源/等价"类措辞 | 约 **190** 处 | 守卫生态在大量承担"防漂移"职责 |

`createHost()` 是一个 **1576 行的闭包**（`js/host.js:353–1929`，内含 294 个定义），
几乎所有主面板↔插件的边界都在它里面有一份。它是所有"两份"的汇聚点。

**这不意味着架构错了** —— 下面第四节会区分"合理分层"与"真的重复"。
真正该动的有 3 处，且都能小步做；另有 4 条边界**至今无人守**（第三节）。

#### B2 值得单独说：两份解析器**语义已经不一致**

同一套语法（`Ctrl+Shift+1` / `mod+K`），两个解析器各自认一套：

| 能力 | `host.js:1577 accelMatches` | `plugin-sdk.js:110 matchCombo` |
|---|---|---|
| 数字小键盘 `Numpad1` | ✅ 认 | ❌ 不认 |
| 功能键 `F5` / `Escape` | ❌ 不认 | ✅ 认 |
| `Key+K` 形式 code | ❌ 不认 | ✅ 认 |
| 别名 `super` | ❌ 不认 | ✅ 认 |
| 别名 `esc` / `space` / `?` | ❌ 不认 | ✅ 认 |
| `mod` → ⌘/Ctrl 映射 | ✅ | ✅（一致） |

也就是说：**同一个 `mod+K`，在宿主级快捷键和插件级快捷键下的行为一致；
但 `F5`、`Numpad1`、`esc` 这些，宿主侧和插件侧认的不是同一套。**

`shortcut-test.mjs`（213 行 / 21 条）**只测了 SDK 侧那一份**，`accelMatches` 全仓零测试，
也没有任何断言要求两者一致 —— 这是典型的"两份实现、只守了一份"。

### C 类 · 插件身份登记分散

`plugins/registry.js`（485 行 / 24 个插件）名义上是唯一真相源，但一个插件的身份散落在：

| 登记点 | 维度 | 是否每个插件都要登记 |
|---|---|---|
| `plugins/registry.js` | 插件 | 必须 |
| `scripts/build-plugins.mjs` | 插件（仅 `runtime:true`） | 部分 |
| `js/invoke-policy.js` | 插件的 `commands` 白名单 | 按需（声明了才要） |
| `js/command-caps.js` | **命令**（不是插件） | 按命令 |
| `js/deps-manifest.js` | npm 包 | 按包 |
| `js/runtime-deps.js` | 运行时包链路 | 按包 |
| `dist-integrity-test.mjs` | 产物拷贝名单 | 部分 |
| `build-entry-test.mjs` | `PLAIN_PLUGINS` 名单 | 部分 |
| `runtime-plugin-test.mjs` | iframe 的 `runtime:true` 标记 | 部分 |

实测（24 个插件 id 在各点的出现次数）显示：**多数点都是"按需登记"**，
所以"少登记一处"不会报错，只会静默失效。

> 注意：`command-caps` / `invoke-policy` / `plugin-admit` 三层是**维度不同**
> （命令定级 / 插件白名单 / 代码准入扫描），**不该合并**。这一条不要动。

### D 类 · 至今无人守的边界（4 条）

| # | 边界 | 风险 | 为什么现在没出事 |

## 四、架构评估：哪些合理，哪些该动

### ✅ 合理的，不要动

1. **`command-caps` × `invoke-policy` × `plugin-admit` 三层** —— 维度不同（命令 / 插件 / 代码），是真正的分层，不是重复
2. **`buildCtx` 已经收口** —— module 与 iframe 两条装载路径共享 ctx 构造（392 行），这是有效收敛
3. **元守卫体系** —— `test-registry-test.mjs` 守"测试有没有被跑"，regression-guard §6 守"守卫自身"，
   `dead-class-test` §8 守"幽灵规则只增不减"。这套"防止守卫自己失明"的设计是对的，别削弱
4. **每一条 A 类边界都有两侧接线断言** —— 这是这套架构最扎实的地方

### 🔧 该动的（按性价比排序）

#### 建议 1 · 把 B1/B2 抽成共享模块（低风险，收益明确） —— ✅ **已完成**（2026-11-01）

新建（或并入既有共享层）一个纯数据/纯函数模块，两侧都 import：

- 存储键：`storeKey(id, k)` / `storePrefix(id)` / `cfgKey(id)`
  → 消掉 `host.js`(3 处) + `plugin-sdk.js`(2 处) + `plugin-config.js`(1 处) 共 6 处拼接
- 快捷键：`parseCombo` + `matchCombo` 作为唯一实现，`accelMatches` 改为调用它
  → 顺带让宿主级支持 `F5` / `esc` / `Numpad`（现在不支持，是缺陷不是特性）

**代价**：小。都是纯函数，行为可对照。
**守卫**：加一条"B1/B2 不得再出现第二份"的断言（这两条判据简单，误报率低）。

#### 建议 2 · `createHost()` 拆分（中风险，收益最大）

1576 行闭包里现在有 294 个定义，职责至少 9 类：

| 职责 | 代表位置 |
|---|---|
| 注册表加载 | `:236` `loadRegistry`、`:311` `saveCustomPlugins` |
| 服务宿主 | `:497` `ensureService`、`:566` `callService` |
| 挂载（module/iframe 两条） | `:942` `mountModule`、`:1051` `mountIframeView` |
| 主题推送 | `:1801` `syncThemeToInstance`、`:2178` `varsForPlugin` |
| 快捷键 | `:1603` `registerAppShortcut` |
| 侧边栏注入 | `:1639` `addSidebarItem` |
| 存储与清理 | `:1942` `purgePluginStorage` |
| 插件顺序 | `:2524` `pluginOrder` |
| 错误诊断 / 桥接 / MCP 清理 | `:2291`、`:1416`、`:1969` |

**不建议一次拆完**。建议先拆出两个最独立、边界最清晰的：
`serviceHost`（服务宿主，已有 `service-plugin-test` 全套守护）和 `diagnostics`（错误诊断，
已有 `err-diag-test`）。这两块拆出去后，剩下的挂载/主题/快捷键仍共享 `state`，风险可控。

#### 建议 3 · 插件身份加一条"总守卫"

不需要把所有派生点合并成一份（它们维度不同、不该合并），
只要加一条断言：**registry 里每个 id，在各派生点的归属是确定的（登记 / 明确不需要登记）**。

现在缺的正是这一条 —— 所以"少登记一处"永远静默。

#### 建议 4 · D1（沙箱级别 ↔ 能力探测）挂钩

`agent-flow` 的 CLI / watch / webhook 三个功能都依赖 Tauri 事件通道，
而 `hasTauriEvents()` 不判 isolated。最小改法：宿主已经把 `isolated` 传进插件
（`host.js:1189`），把它纳入能力探测；或在隔离态下让这三个功能明确报"不支持"，
而不是停在 running。

## 五、本表是怎么核对的（以及一个反复出现的坑）

- **不靠关键词下结论**。关键词扫描会**同时**产生两种错：
  - *假缺失*：命名不同（`chain-builtins` 不叫 `agent_chain`、`watch.rs` 不叫 `folder_watch`）
  - *假对齐*：命中数来自无关模块（`backup` 51 命中里绝大多数是脑图备份）
- **每一条"两份"都给出两个文件:行号**，不是凭印象
- **B2 的差异是逐条对照两个函数体得出的**，不是猜的
- **重复函数体扫描用归一化 + 相似度**，host.js 与 plugin-sdk.js 之间
  ≥80% 相似的函数对为 **0** —— 说明这两者是**协议两侧**而非复制粘贴，
  这一点纠正了我核对前的预判

### 反复出现的坑（本轮又踩到）

| 坑 | 本轮实例 |
|---|---|
| 只看关键词 → 误判 | 见第三节，我把"5 类事件都有 listen"判成"零 listen" |
| "看着像引用"是子串 | `components/DialogsHub` 含 `components/Dialogs`（此前已栽 3 次） |
| 判据失效导致假绿 | 比假红危险：改错了反而让检查对象消失 |
| 汇总结论前先抽样验证 | 本轮对每个"两份"结论都回读了两处实现 |
