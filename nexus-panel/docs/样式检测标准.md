# Nexus 界面样式检测标准

> 来源：把 `nexus-panel/` 下现有测试脚本的断言**逐条反推**成规范。
> 用途：作为新建界面 / 接入新插件时的**自检清单**，也让其他界面能跑同一套规则。
>
> 每条格式：**要求 · 阈值或判据 · 违反后的实际表现**（最后一项最重要——它说明这条为什么存在）。
> 括号里的编号是原点，便于回查实现细节。

配套脚本：`style-standard-test.mjs`（可执行版，见文末用法）。

---

## 0. 怎么用

1. **新建界面时**：从上往下过一遍，能自动判定的交给脚本，需要人判断的看"违反表现"决定是否放行。
2. **接入新插件时**：第 1、2、3、9、10 条是硬门槛（可自动跑）；第 7、12 条只对自带主题的插件生效。
3. **例外**：每条都允许例外，但**例外必须写在注释里**，并说明为什么——否则后来者会把它"统一"掉。

## 1. 令牌化：不许硬编码

| # | 要求 | 判据 | 违反表现 |
|---|---|---|---|
| 1.1 | 颜色走变量 | 除中性兜底外无裸色值 | 换肤失效，且不报错 |
| 1.2 | 圆角走 `--r-*` | 无裸 px 圆角 | 同页面出现 6/8/10px 三种圆角 |
| 1.3 | 阴影走 `--sh-*` | 无裸 `box-shadow` 色值 | 换主题后阴影方向不跟着变 |
| 1.4 | 时长走 `--dur-*` / 动画走 `--anim-*` | 无裸 ms/s | 减少动效兜底拦不住 |
| 1.5 | z-index 走 `--z-*` | 无裸数值 | 后来者加浮层只能靠猜该排哪一档 |
| 1.6 | 悬停提亮走 `--hover-bright` / `--hover-bright-strong` | 无裸 `brightness()` | 各处 1.06/1.12/1.15 三个数纯属手调 |
| 1.7 | 描边粗细走 `--ctl-faux-bold` | 无裸 `font-weight` 改描边 | 见 3.2 |
| 1.8 | 禁用态弱化走 `--ctl-disabled-opacity` | 无裸 opacity | 各处禁用深浅不一 |

**1.6 为什么分两档**：可感知度取决于元素面积——大块按钮上 15% 会闪，小徽章上 6% 基本看不见。统一成一个数两边都不对。

**关于"变量本身"**：变量名暗示层次但值却相同时（如 `--title-1-fw` / `-2-fw` / `-3-fw` 都指向 600），比直接写裸值更误导。**名字必须有对应的值差异**。（§34）

## 2. 对比度与可读性

阈值表（纯计算即可判，不依赖浏览器）：

| 前景 | 背景 | 最低 | 说明 |
|---|---|---|---|
| `--text` | `--bg` / `--surface` / `--surface-raised` | **4.5** | 正文 |
| `--text-soft` | `--bg` | **4.5** | 次级正文 |
| `--text-dim` | `--bg` / `--surface` | **3.0** | 说明文字 |
| `--text-mute` | `--bg` / `--surface` | **3.0** | 最弱文字 |
| `--accent` | `--bg` | **3.0** | 强调色需可辨 |
| 角标文字 `--badge-fg` | `--accent` | **4.5** | 见下 |

| # | 要求 | 违反表现 |
|---|---|---|
| 2.1 | 角标文字按强调色明暗派生（黑或白），不写死 `#fff` | 亮黄强调色上白字对比度 **1.09**，等于没有 |
| 2.2 | 画布/节点类：填充对比度 ≥ 2.5、连接线 ≥ 3.0、无填充文字 ≥ 4.5 | 浅画布上白线消失 |
| 2.3 | 层级间可区分：相邻级 L\* 差 **≥ 8**；最底层与画布底 ΔL\* **≥ 2** | 层级糊成一片 |
| 2.4 | 深色底上的浅色文字、浅色底上的深色文字，按基调分两档写 | 品牌色在另一基调下只剩 1.1~2.5 |

**必须在感知均匀空间评估**：用 L\* 而不是线性亮度 Y。Y 在暗部数值极小，会严重低估深色端差异——实测同一个方案，用 Y 算"极差 11.7 倍"、用 L\* 算只有 1.8 倍，结论完全相反。

## 3. 文字属性

| # | 要求 | 判据 | 违反表现 |
|---|---|---|---|
| 3.1 | 字号走语义档 | 无裸 px（图标字形除外） | 同一语义散成 4~5 档 |
| 3.2 | 状态变化**不改字重**（hover 只换色） | hover/active 里无 font-weight | 并排按钮一 hover 宽度就抖 |
| 3.3 | 字重走 `--fw-strong/mid/normal`，无裸 600/700/normal | — | 想改"标题字重"要动三行 |
| 3.4 | 行高收敛到三档 `--lh-tight/normal/relaxed` | 无裸倍数（`1` 除外） | 1.5 与 1.55 差半个像素却让区块对不齐 |
| 3.5 | 字体族走 `--font-sans` / `--af-mono`，不硬编码整套栈 | — | 外壳换字体、插件这里不变，且不报错 |
| 3.6 | 等宽文本走**独立的等宽档** | 等宽处用 `--fs-code` | 等宽字体同 px 下视觉更小，与相邻比例字体对不齐 |
| 3.7 | 同一容器内不混档（如胶囊里标签 10px 配内容 11px） | 同容器档位 ≤ 4（按**实际像素**去重） | 看着就是没对齐 |

**语义档参考值**：title 13 / body 12 / note 11 / micro 10 / code 11。
**3.7 去重必须按像素**：`--fs-note` 与 `--fs-code` 都是 11px，按变量名算会得出 5 档的假结论——用户看到的是像素，不是变量名。

**刻意例外（须注释）**：图标字形的 `font-size` 是"画多大"不是"字多大"，不参与统一。

## 4. 层级、圆角、阴影、间距

| # | 要求 | 违反表现 |
|---|---|---|
| 4.1 | z-index 全部走 `--z-*`，并按语义命名档位 | 看不出某层该排在哪 |
| 4.2 | 圆角走档位；卡在两档之间的值（如 5px 介于 4 和 6 之间）要**新增档**而不是写死 | 长期没人敢动，23 处写死 |
| 4.3 | 阴影走 `--sh-*`，立体态三态（外凸/抬升/内凹）用**同一套几何、只改方向** | 观感不像同一块材料被按下去 |
| 4.4 | 间距：至少**冻结基线**（只增不减），新增优先走令牌 | 全量令牌化风险大，但至少挡住继续恶化 |

**4.4 的现实约束**：agent-flow 有 632 处写死，高频值含 5px/7px 这类奇数，而共享 `--sp-*` 是偶数体系——硬套会改变观感。所以策略是冻结而非强改。

## 5. 状态与交互

| # | 要求 | 违反表现 |
|---|---|---|
| 5.1 | **状态规则不改布局属性**（width/height/padding/margin/font-size） | 悬浮时元素尺寸变化 → 邻居被挤动 |
| 5.2 | 悬浮高亮用 `border-color`，不用 `border` 简写 | 简写会重置粗细（medium≈3px），把卡片撑大 |
| 5.3 | 悬停位移用 `translateY(-1px)` + 浅阴影，**不用大阴影** | `-3px` 配 `0 8px 24px` 在工具界面里浮夸 |
| 5.4 | 按压用 `scale(.97)`，不用 `scale(1.1)` | 游戏化反馈不适合工具界面 |
| 5.5 | **纯容器类不给交互反馈**（长得像卡片 ≠ 可以点） | 设置面板每个分区底板点击有按压动画，点了却没反应 |
| 5.6 | 可点击容器用显式标记类（如 `.nx-tap`） | 无法区分"能点的卡片"和"只是容器" |
| 5.7 | 禁用态光标统一 `not-allowed`（不用 `default`） | 用户不知道为什么点不动 |

**5.5 是最容易犯的**：判据必须是"是否可交互"，不是"是否长得像卡片"。按外观分配交互反馈必然误伤。

## 6. 语义变量边界（最容易踩）

| # | 要求 | 违反表现 |
|---|---|---|
| 6.1 | `--border` 是**风格开关**：新拟态下为 `transparent`（靠阴影塑形） | — |
| 6.2 | `--divider` 是**保证可见的边界**：任何风格都有颜色 | 混用 → 新拟态下 26 处分隔线 + 10 处无底色控件全部消失 |
| 6.3 | 输入框边框用**独立变量**，不与结构线共用 | 新拟态下输入框无边框；原生模式下不跟基调、对比度飙到 12~14（内容边框只需 1.2~1.5） |
| 6.4 | 分界两侧即使同色也要能看出分界 | 侧栏与画布连成一片 |
| 6.5 | 主题产出的变量**全部登记进 THEME_VARS** | 算了正确的值却没写出去，实际生效的是写死兜底 |
| 6.6 | CSS 兜底必须有**深浅两档** | 首屏几十毫秒用错档，然后跳一下 |

**6.3 的关键**：`transparent` 是合法值，`var(--border, fallback)` 的兜底**不会生效**——不会退回深色，而是直接透明。

## 7. 主题定义规范

每套主题必须满足：

| # | 要求 | 违反表现 |
|---|---|---|
| 7.1 | 声明 `base`（light/dark）与 `style` | 深浅判定无从下手 |
| 7.2 | 定义核心变量：`--bg` `--surface` `--surface-sunk` `--surface-raised` `--sh-dark` `--sh-light` `--text` 系列 `--accent` | 派生量全空 |
| 7.3 | **凹陷面/阴影方向正确**（浅色：sh-light 更亮、sh-dark 更暗） | 立体感反向 |
| 7.4 | 派生量齐全：`--accent-glow` `--hairline` `--scroll-thumb` `--mask` | 滑块、滚动条、遮罩丢失 |
| 7.5 | 风格 × 基调**每种组合至少一套** | 用户挑不到想要的那档 |
| 7.6 | 每种风格**深浅各两套以上** | 单一基调撑着，切换即翻车 |
| 7.7 | 扁平主题 `--border` 非透明；玻璃主题 `--blur > 0`、带背景渐变 | 风格特征不成立 |
| 7.8 | 主题 id 唯一；自定义 id 带前缀、不与内置撞车 | 覆盖内置主题 |
| 7.9 | 并入时**深拷贝** | 编辑预置主题会改掉模块常量，刷新后所有文档跟着变 |
| 7.10 | 删除要记进移除名单，否则下次启动又并回来 | 删除按钮等于坏的 |
| 7.11 | 切换主题时**主动清掉**新主题没定义的变量 | 从定义了 `--r-xl:12px` 的扁平主题切回新拟态，圆角停在 12px（内联压住 CSS） |

## 8. 玻璃 / 特殊风格

| # | 要求 | 违反表现 |
|---|---|---|
| 8.1 | 磨砂 = `blur` + **saturate** + 颗粒层 + 边缘高光，四层缺一不可 | 只有 blur 是"蒙尘的塑料片"，不是磨砂 |
| 8.2 | `saturate(140%~185%)`（深色高、浅色低）补回被模糊吃掉的饱和度 | 透出来的颜色发灰发闷 |
| 8.3 | **saturate 必须与 blur 写在同一条声明** | 拆两行时后者整条覆盖前者，只剩饱和度、模糊没了 |
| 8.4 | 颗粒用 `::before` + `pointer-events:none`，平铺 128px 小块，不动画 | 用 `::after` 会盖在文字上；整块面板点不动；动 `baseFrequency` 每帧重算湍流场 |
| 8.5 | 颗粒强度上限 **0.15** | 超过是可见噪点而非质感 |
| 8.6 | 浅色玻璃用 `soft-light`、深色用 `overlay` | 浅底上 overlay 显脏 |
| 8.7 | 面板不透明度 ≥ **0.88**、浮起/凹陷 ≥ 0.92、弹窗 ≥ 0.94 | 主面板文字透出来与面板文字叠在一起，两边都看不清 |
| 8.8 | 表面色**从背景色派生**（只动 HSV 的 V/S，保持 H），不用白色叠加 | 深色低透明度后面板发灰发亮、色相被稀释（极光玻璃的紫变成灰） |
| 8.9 | 色相偏离 ≤ **12°**；深色 V 增量 ≤ **10%**；饱和度 ≥ 背景的一半 | 被中性白洗淡 |
| 8.10 | 弹窗只吃**一半幅度** + 有**不透明度地板** | 面板变透弹框跟着透，浮在主面板上没法读 |
| 8.11 | 透明度滑块语义与实现一致（标签写"调高更透"，实现就得 alpha 更低） | 调高反而更实，与描述相反 |

**8.8 的实测**：深色底 7% 白叠加会把亮度抬 7.6 个 L\*——7% 看着小，但白色和深色底差得远。同色系派生后降到 2.9~4.9。

## 9. 类名卫生

| # | 要求 | 违反表现 |
|---|---|---|
| 9.1 | **代码用了但 CSS 没定义**的类名 = 0 | 元素裸奔（没间距、没边框、位置乱），且不报任何错 |
| 9.2 | CSS 定义了但代码没用的类名：冻结基线，只增不减 | 误导后来者以为存在这条路径 |
| 9.3 | 无"被截断的规则"（前一条规则缺 `}` 导致与下一条连读成后代选择器） | 整段样式失效——**恰恰是那条注释想防止的事** |
| 9.4 | 白名单必须带**反向校验**：已被修好的项要提醒移出 | 白名单只增不减，慢慢变成"什么都往里塞" |
| 9.5 | 死样式吸纳前先读原实现的注释 | 判为"重复实现"删掉，结果把自有三态砍成两种手感 |

**9.1 是反向的**：此前只查"CSS 有、代码没用"（死样式，危害是冗余），漏掉"代码用了、CSS 没有"（真疏漏）。后者不报任何错。

**写这类检查的三个坑**（都会让防线静默放水）：
- 扫到**测试文件里的示例串**
- 扫到**注释里的举例**
- 扫到**扫描器自己的源码**（它用示例类名做单测）

## 10. 可访问性

| # | 要求 | 违反表现 |
|---|---|---|
| 10.1 | 尊重 `prefers-reduced-motion`，且兜底覆盖**伪元素**与 `transition`/`scroll-behavior` | 位移引发前庭不适 |
| 10.2 | 一次性入场动画在减少动效下**直接去掉**；转圈**仍持续转动**（覆盖 `iteration-count`） | 转圈停了让人以为卡死 |
| 10.3 | 焦点环用 `outline` 而非 `box-shadow` | 后者会被立体阴影覆盖 |
| 10.4 | 用 `:focus-visible` 而非 `:focus` | 鼠标点击也出现环 |
| 10.5 | 输入框键盘进来时也有环（与指针点击区分） | 键盘用户找不到焦点 |
| 10.6 | 触摸目标 ≥ 44px，用 `::after` 扩展而非 padding | padding 会把邻居挤开 |
| 10.7 | 触摸扩展**不自动套用到图标按钮** | 密集时重叠误触 |
| 10.8 | 错误态用 `aria-invalid` 而非只靠 `:invalid` | 后者一进页面就满屏红 |
| 10.9 | 容器级错误态只描边**不改底板** | 满屏红底让人以为数据丢了 |
| 10.10 | 强制色模式下给卡片补系统色描边；勾选框显形 | 高对比度模式下边界消失 |

## 11. 布局与响应式

| # | 要求 | 违反表现 |
|---|---|---|
| 11.1 | 滚动容器显式 `min-height: 0` | flex 子项撑破容器、滚动失效 |
| 11.2 | 百分比高度链上每一级都有显式 `height: 100%` | 子级百分比高度失效 |
| 11.3 | 断点按**容器宽度**（iframe 宽度）而非视口 | 插件在窄栏里不响应 |
| 11.4 | 工具栏/按钮行可 `wrap` | 11 个按钮挤在 686px 里 |
| 11.5 | 标题可收缩省略，**操作区不参与收缩** | 按钮压扁比标题省略更难用 |
| 11.6 | 单行省略工具类带 `min-width: 0` | flex 子项默认 `auto`，不写就不生效 |

## 12. 插件基调适配

| # | 要求 | 违反表现 |
|---|---|---|
| 12.1 | `manifest.theme` 语义是**与面板的关系**（`dark`=同基调不适配），`light`=相反需适配 | 当成"插件自身颜色"→ 深色下碰巧对，一切浅色必翻车 |
| 12.2 | 插件**自己上报**的基调优先于静态声明 | 跟随主题的插件声明会失效 |
| 12.3 | `panelBase` 用 **getter** 而非一次性求值 | 切换主题后复用旧值 → 施加本不该有的反转 |
| 12.4 | 基调只看底色，不用其他变量的存在性去否决 | `--text` 漏传时底色再亮也判成深色，且不报错 |
| 12.5 | 读了外壳变量的插件标 `followsTheme`；标了的确实读（无错标） | 该加的滤镜没加，深色面板上留一块刺眼的白 |
| 12.6 | 基调变化时**重报**，且重报排在"变量已生效"回执之前 | 白等一轮还得多闪一次 |
| 12.7 | 切主题时**先清再施加**（幂等） | 快速连点会层层叠加滤镜 |

---

## 13. 通用控件收口

| # | 要求 | 违反表现 |
|---|---|---|
| 13.1 | 同名控件（`.nx-btn`/`.p-btn`/`.mm-btn`）在**同一条规则**里 | 各写一份，改一处漏两处 |
| 13.2 | 裸 `button` 兜底：`border: 0; font: inherit`，且写在按钮类**之前** | UA 给 2px outset 系统色边 → 深色下一圈白；UA 字体是 Arial 不继承 |
| 13.3 | `select option` 背景/文字走变量，且带 `--surface` 兜底 | 只引部分 CSS 的插件拿到空值 |
| 13.4 | 实底按钮文字色用派生的 `--badge-fg`，不写死 `#fff` | 亮色强调色上白字不可见 |
| 13.5 | 滑块 WebKit 与 Firefox 伪元素**分开写** | 写一起会被整条丢弃 |
| 13.6 | 勾用内联 SVG 而非字符，不用 `clip-path` | 字符受字体影响各平台不一致；clip-path 会连背景一起裁掉 |
| 13.7 | 数据驱动的调节项**必须有界面入口** | 逻辑全就绪，界面从来没渲染过 |

## 附：可执行版用法

```bash
cd nexus-panel
node style-standard-test.mjs                        # 全量体检（存量记「待办」，不算失败）
node style-standard-test.mjs --dir plugins/xxx      # 按新界面标准严格判定（推荐用于新界面）
node style-standard-test.mjs --dir plugins/xxx --classes   # 额外跑类名卫生（需源码）
node style-standard-test.mjs --strict               # 全量也严格
node style-standard-test.mjs --json                 # 输出 JSON，便于接入 CI
```

### 严格度为什么要分档

全量跑会把存量问题算成失败 → 新界面永远红着、没人看；
假装存量是绿的也不诚实。所以：
- 指定 `--dir` 时按**新界面标准**严格判定（有债就红）
- 全量体检时令牌化类条款记「存量待办」，只提示不计失败

### 判定时的三个豁免（都是踩过坑才加的）

| 豁免 | 理由 |
|---|---|
| `var(--x, 兜底)` 里的兜底不算硬编码 | 不引 tokens.css 的插件就靠它，判成违规会误报一大片 |
| `:root{}` 与 tokens.css 不算硬编码 | 那是**定义**令牌的地方，写具体值是本职 |
| 就近写了原因的硬编码放行 | SVG data URI 读不到变量、叠在未知内容上的控件要自保 |

另有两条几何豁免：`border-radius: 50%`（画圆）、`0 3px 3px 0`（多值贴边）都不算档位值；`z-index: 0` 是重置不是排档。

第三方库（`editor/` `vendor/` `kityminder` 等）不参与检测——拿我们的标准量外部产物只会得到噪音。

### 加新规则的原则

1. **先写"违反表现"**。说不清后果的规则，说明它不该存在。
2. **做了破坏验证才算数**。改回旧写法要能报红，否则断言可能在放水（实测踩到过三次：匹配到注释、结束点落在起点之前、读到了扫描器自己的示例类名）。
3. **例外写进注释**，并加一条"例外必须注明"的断言，防止被人"统一"掉。
