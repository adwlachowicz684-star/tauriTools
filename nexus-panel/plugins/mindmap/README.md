# 思维导图插件（mindmap）

把 `junction_link` 里的 C# WPF 思维导图模块移植成 Nexus Panel 插件。

## 结构

```
plugins/mindmap/
├── index.html            插件页面（工具栏 / 侧栏 / 画布页签）
├── index.js              主入口：状态、持久化、撤销栈、导入导出
├── editor-bridge.js      与内层编辑器的命令桥接
├── store.js              IndexedDB 持久化（工作簿 / 主题 / 快照 / 附件）
├── workbook.js           多画布模型 + JSON / Markdown 序列化
├── themes.js             10 个内置主题 + 6 个布局模板元数据
├── io.js                 文件导入导出、附件 Blob 存储
├── xmind.js              XMind(.xmind) 导入导出（含自写 zip 容器，零依赖）
├── panels.js             右侧属性侧栏四页（主题 / 标签 / 样式 / 文件）与浮层
├── layout-thumbs.js      六个布局模板缩略图（内联 data URL，取自 WPF 原版资源）
├── filelist.js           左侧文件库（多文档列表 / 文件夹 / 拖拽归类）
├── styles.css            样式（全部走外壳主题变量）
└── editor/               kityminder 内核（取自 junction_link 的 dist/，4 个文件）
    ├── index.html
    ├── kity.min.js
    ├── kityminder.core.min.js
    └── kityminder.core.css
```

## 为什么是嵌套 iframe

插件层与编辑器层**同源**，但仍是各自独立的文档：

- 编辑器的 `#minder-container` 是 `position:absolute; inset:0`，天生要铺满整个视口。若合并成单页，会盖住工具栏，必须改写布局 CSS；
- 嵌套后编辑器 1900 多行代码里 **95% 是脚本，一字未改**就能跑，以后上游更新直接覆盖 4 个文件；
- 命令调用是 `iframe.contentWindow.__minder.xxx()` 同步直调，不用再拼 JS 字符串交给 `ExecuteScriptAsync`。

编辑器页面取自 `junction_link/数据/plugins/kityminder/dist/`（运行时实际加载的那份），
仅把 5 处 `window.chrome.webview.postMessage(...)` 抽象成 `hostPost()`，
WPF 宿主行为完全不变。

## 相比原 C# 实现的改动

| 项 | 原实现 | 现在 |
|---|---|---|
| 命令调用 | 拼 JS 字符串 + `ExecuteScriptAsync` | 同源同步直调 |
| U+2028/2029 破坏语法 | 需转义规避 | 不存在该问题 |
| Promise 返回值 | 不等 Promise，需轮询 `pollExportPng` | 直接 `await` |
| 附件 | 存本地文件路径，文件移动即失效 | 存 Blob 进 IndexedDB（XMind 导出时打进包内，换机可还原） |
| 持久化 | `数据/` 目录 JSON 文件 | IndexedDB（实时缓存）+ 显式导出文件 |

## 数据与安全

- **实时缓存**：编辑停止 800ms 后写入 IndexedDB；按配置间隔自动留一份快照（滚动保留 10 份），内容没变不写盘；插件卸载前再兜底存一次。闪退后重开即为最新内容。
- **显式存档**：`.xmind`（与 XMind 官方互通）、`.json`（保留全部私有字段）、`.txt`、`.md`、`.svg`、`.png`。
- 落盘优先用 File System Access API（能弹真正的保存对话框），不支持时回退 `<a download>`。

## 界面分布（对齐 C# MindMapPanel）

按 `MindMapPanel.xaml` 的四行两列重排过。此前四块面板全堆在画布**左侧**，
右侧栏从来不存在。

```
┌──────────────────────────────────────────────┐
│ 顶部工具栏（导入导出 / 插入 / 编辑 / 选择 …） │  Row 0
├──────┬───────────────────────────┬───────────┤
│ 文件 │                           │  属性侧栏 │  Row 1
│ 库📚 │          画布              │  276px    │
│ 默认 │                           │ 主题/标签 │
│ 收起 │                           │ 样式/文件 │
├──────┴───────────────────────────┴───────────┤
│ 画布页签条（页签横向滚动 + 最右 ＋）          │  Row 2
├──────────────────────────────────────────────┤
│ 状态条                                        │  Row 3
└──────────────────────────────────────────────┘
```

| 位置 | 内容 | 与 C# 的差异 |
|---|---|---|
| 左 · 文件库 | 多文档列表 / 文件夹 / 拖拽归类 | **C# 没有**（Web 版多文档功能），故默认收起，点 `📚` 展开 |
| 中 · 画布 | kityminder 编辑器 | 一致 |
| 右 · 属性侧栏 | 主题 / 标签 / 样式 / 文件 四页 | 宽度取 C# 的 `Width="276"`；无差异 |
| 顶栏最右 | 四个属性页签 | 一致（C# 的 `Grid.Column=14`） |
| 底 · 页签条 | 画布页签 + 最右 `＋` | 一致（C# 也是 `ScrollViewer` + 右侧 `＋`） |
| 底 · 状态条 | 操作反馈 | 一致（C# 在 `Grid.Row=3`） |

**页签放在顶栏最右，不占侧栏高度**：侧栏只有 276px 宽，纵向空间本就紧张，
顶部再压一条页签条等于凭空少一屏内容。页签与侧栏通过 `onPage` 回调保持同步 ——
侧栏会自行切页（例如点节点附件时跳到「文件」页），此时顶栏高亮也要跟着变，
所以不能只在点击时更新。

**状态条从页签条里拆了出来**：原先两者挤在同一行，页签一多就把状态文字顶得
忽长忽短；拆开后成独立两行，与 C# 一致。

## 文件库（左侧面板）

点左侧图标条的 `📚` 展开/隐藏。**默认收起** —— C# 原版没有左栏，收起时画布
左右只剩属性侧栏一侧占位，更接近原版观感。展开状态记在设置里，下次进来保持。

**一个文件 = 一份工作簿**（含多张画布），与右侧属性侧栏是两回事：

| 面板 | 作用对象 |
|---|---|
| 左侧文件库 | 整个文档 —— 切换编辑哪个脑图、建文件夹归类 |
| 右侧属性侧栏 | 当前选中的**节点** —— 样式 / 标签 / 主题 / 附件 |

交互：

- **打开**：点列表项直接切换（先收当前编辑并落盘，保存失败会拒绝切换，避免丢内容）
- **新建**：`＋` 建脑图、`📁` 建文件夹
- **归类**：把文件拖到文件夹上即归入，拖回根目录区域即移出
- **折叠**：点文件夹标题行
- **删除**：删文件夹只删壳，里面的脑图移到根目录（不连带删除）；删脑图需确认

数据布局（`store.js`）：

```
fileindex   [{ id, name, folderId }]   列表索引，不含画布内容
folders     [{ id, name, collapsed }]
doc:<id>    单个脑图的内容（一份工作簿）
```

列表只存轻量索引，不存画布内容 —— 否则每次打开都得把所有脑图读进内存。

**旧数据迁移**：早期版本整个插件只有一份工作簿（存在 `workbook` 键下）。
首次进入会把它迁成第一个文件「我的脑图」，老用户不丢内容。

## XMind 互导

`xmind.js` 对齐 `junction_link/src/Services/XMindConverter.cs`：

- 包结构：`content.json`（XMind 官方标准）+ `kityminder.json`（本工具无损快照）+ `metadata.json` + `manifest.json` + `resources/`
- 读取三档优先级：无损快照 → Zen/2020+ `content.json` → XMind 8 `content.xml`
- 附件按字节打进包内，导入时解回 IndexedDB，跨机器可还原

底层是自己实现的（C# 的 `ZipArchive` / `XDocument` 在 JS 侧没有等价物）：
zip 容器自写 CRC32 + 原生 `CompressionStream('deflate-raw')`，XML 走 `DOMParser`，**零第三方依赖**。

## 画布跟随外壳亮/暗主题

原版画布底色写死 `#1E1E1E` 以贴合 WPF 深色外壳。插件版改为跟随 nexus 外壳主题：

- 编辑器页面的画布相关配色抽成 `--km-*` CSS 变量（容器底色、内描边、搜索面板、加载遮罩），
  默认值为原版深色，**WPF 宿主不调用新门面时行为完全不变**；
- 插件层从外壳主题变量派生画布配色（`deriveCanvasTheme`），`postMessage` 传给内层编辑器页
  —— 内层是独立文档，外壳注入的 CSS 变量进不去；
- 内核 `setTheme()` 会执行 `renderTarget.style.background = getStyle('background')`，
  内联样式优先级高于 CSS 规则，所以门面在每次 `setTheme` / `importJson` 之后会重新套一次；
- 编辑器重载、页面初始化早于消息到达两种情况都已覆盖（门面就绪后补套 pending 值）。

**分工**：外壳主题决定画布明暗，kityminder 主题决定节点配色。节点都绘制了不透明底色，
因此画布变色不影响节点内文字的可读性。

### 两个值得记的判断

**M1 的竞态是修复的一部分，不是可选优化。**
改成写 `doc:<id>` 之前，自动保存写的是没人读的 `'workbook'` 键，
反而意外躲过了「迟到的保存盖到新文件上」。改对键之后这个风险才真实存在，
所以 `doSaveInner` 在 `await` 前后各比对一次 `currentFileId`，不匹配就丢弃这次保存。

**但光有那句守卫还不够 —— 它依赖「捕获 id」与「写入」之间没有 `await`。**

```js
const savedFileId = currentFileId;                    // ① 捕获
//   ← 这里一旦插入 await，保护就静默失效
const saved = await store.doc(savedFileId).save(workbook);   // ② 写入
if (savedFileId !== currentFileId) return;            // ③ 守卫
```

`workbook` 是闭包变量，在 ② **调用那一瞬间**求值。① ② 之间没有让出点时，
它还是捕获那一刻的对象，安全；一旦中间让出，`switchToFile` 可能已经跑完 ——
于是 `savedFileId` 还是旧 id，`workbook` 却已换成新文件的内容，
结果是**用新文件内容覆盖旧文件**。而 ③ 只能拦住状态栏和备份，拦不住已发生的写入。

已实测（测试里的对照组）：两组代码守卫完全相同，只差中间有没有 `await`，
有 `await` 的那组 `doc:f1` 直接被写成 f2 的内容。

因此 `mindmap-test.mjs` 除了验证守卫存在，还锁住「① ② 之间恰好一个 `await`，
且它就是 save 调用本身」。插入一个看似无害的 `await Promise.resolve()` 会让测试变红 ——
这条断言做过变异验证，不是摆设。

**M7 只改 `switchSheet`，没改 `switchToFile`。**
清单建议两处都加，但 `switchToFile` 的三个调用点里：

- `openFile` 已经先 `capture()` + `await persist()`，重复落盘是白写一次；
- `deleteFile` 调它时**当前文件刚被删掉**，此时 `persist()` 会把内容写回已删除的
  `doc:<id>`，留下一份没人引用的垃圾数据 —— 这正是 `deleteFile` 注释里点明的坑。

所以只在 `switchSheet` 补落盘。

## 异步与存储的错误处理约定

这块踩过坑，写成约定以免后续改回去：

1. **`store.set` 失败是「返回 false」而不是抛异常**。所以检查写入结果必须判返回值，
   只写 `try/catch` 等于静默丢弃。已统一：`persist()` / `doSaveInner()` / `saveThemes()` /
   `backupNow()` / `setBackupMinutes()` / `setAnimate()` 全部判返回值并提示。
2. **onclick 拿不到 Promise**。所有面板/工具栏入口经 `guard()` 或 `api` 层包装，
   异步失败落状态栏，不留 unhandled rejection。`doSave()` 跑在定时器里，单独包一层。
3. **画布 `content` 运行时是对象**（`exportJson()` 返回对象，仅序列化落盘后才是字符串）。
   任何比较都必须按内容：`sameSnap()` 比较、`fingerprintSheets()` 序列化后再拼。
   直接 `===` 或用字符串拼接会让「内容变了没」的判断永远失效
   （对象转字符串是 `[object Object]`，备份去重会退化成只认画布增删/排序）。
4. **Blob URL 要释放**。`getAsset()` 每次调用都新建一个 URL；交给浮层的由浮层关闭时
   `revoke`，走下载路径的就地释放，否则反复点附件会一直堆积。

### 行内编辑：不只是回车才提交

早期版本「输入完必须按回车，点旁边就白输」。根因在 kityminder 的两处设计：

```js
// text 命令的执行体：只写「当前选中的节点」
execute: (minder, v) => { const n = minder.getSelectedNode(); n && (n.setText(v), …) }
// 且 queryState 要求选中数恰好为 1，否则命令被直接拒绝（不报错、不写）

// select 模块的 mousedown：点画布会立刻改/清选中
b ? this.select(b, true)                          // 点到节点 → 改选中
  : (this.removeAllSelectedNodes(), …)            // 点空白   → 清空选中
```

于是「编辑中 → 点旁边」有两种坏结果：点空白 → 选中被清空，命令被 `queryState`
拒绝，输入**静默丢失**；点别的节点 → 选中改了，文字被写到**错误的节点**上。

**修复**：两道保险，且互相独立。

| 位置 | 作用 |
|---|---|
| `document` 捕获阶段的 `mousedown` | 抢在内核改动选中**之前**提交。只靠 blur 不够 —— SVG 不可聚焦，焦点何时转移取决于内核是否抢焦点，时序不可依赖 |
| `closeTextEditor` 内 | 提交前若 `getSelectedNode() !== editLayer.node` 就先 `select` 回来，让提交与「当前选中是谁」彻底解耦 |

顺带把 `editLayer = null` 提到 `execCommand` 之前：`execCommand` 会触发渲染与
事件，万一重入会二次提交。

### 行内编辑：怎么做到「像直接在节点里改」

先说原理边界：**SVG 的 `<text>` 没有 `contenteditable`**（SVG 1.1/2 都不提供原生
文本编辑），所以必然要一层 HTML 编辑层 —— 做不到真的在 SVG 节点里改字。
能做的是让它**看起来**就在节点里。之前的差距来自四处：

**1. 缩放后字号与位置对不上（量纲混用）**

```js
fontSize = getComputedStyle(tx).fontSize   // CSS 像素，**不含**缩放
box      = tx.getBoundingClientRect()      // 屏幕像素，**已含**缩放
```

画布 zoom 走的是 `paper.setViewPort({zoom})` → SVG transform，它**不改
`font-size`**，只改变换矩阵。于是 zoom=50% 时节点文字在屏幕上只剩 7px，
编辑层仍按 14px 渲染。修法：字号与行高都乘 zoom，位置尺寸保持屏幕像素。

**2. 只取了第一行**

`g.getElementsByTagName('text')[0]` 拿的是第一个 `<text>`，而 kity 的文字是
**每行一个 `<text>`**（源码 `eachItem(... setY(m + a*i*h))` 逐行排布）。多行节点
编辑时编辑层只盖住第一行，下面几行还露着 —— 重影就是这么来的。改用整组 `<g>`
取 bbox，行数按 `<text>` 数量算，`line-height = 总高 / 行数`（直接用总高会让
单行文字垂直偏移）。

**3. 原 SVG 文字没隐藏**：编辑层盖在上面，任何 1px 偏差都会看出叠影。
现在编辑期间 `visibility:hidden`，关闭时恢复。

**4. 宽度写死 + `overflow:hidden`**：输入超长直接被截断，而节点文字是自适应
的。改为 `width:auto` + `min-width` 保底。

另外编辑期间画布一变换（缩放/平移）就先提交关闭：编辑层是绝对定位的 HTML，
不跟着 SVG transform 走，不处理就会飘在半空。

### 前提：焦点必须在画布上

kityminder 的所有键盘输入都来自一个隐藏的 `<input class="km-receiver">`，
它由内核自己在 renderTarget 里创建。**焦点不在这个 input 上时，上面 18 条
快捷键一条都不会生效** —— 这是最容易踩的坑，比快捷键本身更值得记住。

典型表现：点过工具栏的按钮之后，Tab 不再建下级节点，而是在按钮之间跳
（浏览器拿它做焦点导航了）。点一下画布能立刻恢复，因为内核在
`beforemousedown` 里 `focus()` 并 `preventDefault()`。

为了让「点完按钮接着按 Tab」也能用，做了两件事：

| 位置 | 处理 |
|---|---|
| `editor/index.html` | 把「聚焦画布」「插入子节点」暴露成 `window.__minderFocusCanvas` / `window.__minderInsertChild`（与 Tab 共用同一份实现） |
| `editor-bridge.js` | 新增 `focusCanvas()` / `insertChild()`，先给 iframe 的 window 焦点，再调内层门面 |
| `index.js` | `bindTabForward()`：在 window **捕获阶段**拦下 Tab，焦点不在文本控件里就 `preventDefault` 并转送；工具栏按钮 `onclick` 执行后调 `focusCanvas()` 归还焦点 |

为什么用捕获阶段：要在浏览器执行「Tab → 移动焦点」之前拦下来，冒泡阶段已经晚了。
为什么不跨文档冲突：keydown 不跨 iframe 冒泡，焦点在编辑器里时插件层收不到，不会重复触发。

按钮后归还焦点的意义不止 Tab —— Enter / 方向键 / Delete / Ctrl+B 同样依赖 receiver，
点过按钮后会一起失效。放在 `onclick` 末尾而非 `setTimeout`：handler 里若调了
`window.prompt` 这类同步模态，焦点会在用户关掉对话框之后才移动，顺序正好。

### 内核没实现的三个，由本插件补齐

编辑器页面原本的注释写着「core 内置方向键导航、/ 折叠、Alt+1-5 展开层级」，
**这句是错的**。查 `kityminder.core.min.js` 可确认：

- `ArrowUp/Down/Left/Right` **零命中**；
- 键码表里预留了 `isSelectedNodeKey: {37,38,39,40}` 常量，但**全文件无使用处**；
- `/`(191) 同样只登记了键码，没有行为；
- 不存在 `expandToLevel` 命令（`expandSelectedToLevel` 是本页面的门面方法）。

即「常量预留了，行为没写」。现已在 `editor/index.html` 补齐：

| 键 | 行为 |
|---|---|
| `↑` / `↓` | 在兄弟节点间移动，到头不动 |
| `←` | 移到父节点（**只移动，不折叠**） |
| `→` | 进入第一个子节点（当前折叠着会先展开，避免选中隐藏节点） |
| `Ctrl + ←` | 折叠选中分支（不改变选中） |
| `Ctrl + →` | 展开选中分支（不改变选中） |
| `/` | 折叠 / 展开选中节点，来回切换（叶子无效） |
| `Alt+1~5` | 从选中节点展开到第 N 级（更深层收起） |

**方向键只管移动，折叠/展开单独一组** —— 这是对齐 XMind 的做法。
早先版本用的是「两级语义」（`←` 先折叠再上移、`→` 先展开再进入），
实际用起来会「想移动却把分支收起来了」，故改掉。

`Ctrl+←/→` 在 macOS 上按 `Cmd+←/→` 同样生效：内核键码解析里
`ctrl` 与 `cmd` 等价（`case"ctrl":case"cmd":`，事件侧判定 `a.ctrlKey || a.metaKey`）。
这正好避开 macOS 把 `Ctrl+←/→` 占用为「切换桌面」的系统快捷键。

折叠与展开都会触发 `contentchange`，因此会被自动保存接住。

同时修掉一个按键泄漏：外框标签输入框原先只 `preventDefault` 不 `stopPropagation`，
编辑外框标签时按 Enter 会顺带插入一个同级节点、按方向键会跑偏选中。

## 画布上的附件图标

节点附加文件/视频后，图标画在节点**右侧**（`getContentBox().right` 起，
有文件时视频再右移 20 并排）。两个坑：

**不能把 `null` 传给 `fill()`。** core 的 `getStyle('color')` 在不少主题下返回
`null`（只在主题项里查得到才返回值），而 kity 的 fill 是：

```js
fill: function (a) {
    a && node.setAttribute('fill', a.toString());
    null === a && node.removeAttribute('fill');   // ← 删属性
}
```

SVG 缺 `fill` 属性时**默认渲染成黑色** —— 于是图标在深色画布上就是一块纯黑
矩形，看不出是文件还是视频。取不到主题色必须回落到明确颜色（`#AEB6C4`）。

**文件图标的 `fill` 要保持 `none`。** 实心填充会盖住折角那条内部线，
剩下一个没有辨识度的方块；改成描边图标后一眼能认出是「文件」。

图标另带 SVG `<title>`（附件名），悬停即可知道挂的是哪个文件 —— 光看图标认不出来。

## 撤销 / 复制粘贴 / 拖拽：B1 修正 + B2/B3 澄清

### B1 统一撤销栈（真问题，已修）

对照 WPF `Undo`/`Redo`（`MindMapPanel.xaml.cs:2194-2208`）—— 原版只有一个栈。

Web 版原先「优先编辑器栈，拿不到就回退本地快照栈」，**两条路径会在一次撤销
序列里混用**，这是真实的丢数据路径：

1. 连按撤销：编辑器栈有 3 步 → 走编辑器栈；
2. 编辑器栈空 → 回退到**本地栈**再撤销一次；
3. 此时按重做 → `redo()` 先试编辑器栈（它有 3 条待重做！）
   → 重做的是编辑器的那次，**本地那次撤销永远回不来**，且本地 `redoStack`
   留一条孤儿，之后会突然跳到旧内容。

修法：**一次撤销序列只用一条栈** —— `pendingRedo` 锁住这次用的哪条，重做
必须走同一条；编辑器栈空就提示「没有可撤销的操作」，不再跨栈。
新编辑 / 切文件 / 切换画布三处解锁。

### B2 / B3：内核本来就提供（初判有误，不重复实现）

差距清单初稿把「剪切/复制/粘贴节点」和「多选拖拽移动」判为「完全缺失」，
**开工核对后确认内核就有**：

| 项 | 内核实现 |
|---|---|
| B2 | `ClipboardModule` 提供 `copy`/`cut`/`paste` 命令，已注册 Ctrl+C/X/V |
| B3 | `DragTree` 在 `normal.mousedown` 启动拖拽，拖拽源取 `getSelectedAncestors()`，天然支持多选 |

**误判成因**：在 min.js 里搜 `"copy"`/`"cut"`/`"paste"` 三个字符串**零命中** ——
命令写作 `commands:{copy:i,cut:j,paste:k}`，是**标识符**不是字符串。
只看字符串搜索会得出错误结论。

另一处易错点：`copy`/`cut` 没自定义 `queryState`，基类返回 `STATE_NORMAL`(0，
不是 -1)，快捷键回调判定 `-1 !== state` → **能**触发。

故不再重复实现（重复实现还有副作用：自定义命令若也注册 Ctrl+X 会与内核冲突），
改为在测试里加澄清性断言锁住事实。

## 页签拖拽（A53–A57）

对应 WPF `WireSheetDragOnce` 那套指针状态机
（`MindMapPanel.xaml.cs:1394-1700`）：跟随动画 / 死区换位 / 边缘自动滚动 /
插入竖条 / 取消回弹。

### 为什么不用 HTML5 Drag & Drop

原实现用 `draggable=true` + dragstart/dragover/drop，三个硬伤：

1. **拖影由浏览器绘制，无法自定义** —— 跟随动画做不到；
2. **`dragstart` 无死区** —— 手指一抖就进入拖拽，单击切换、双击重命名会被吞；
3. **`dragover` 频率不足以驱动流畅的实时换位**。

改用 Pointer Events 自建状态机（`tab-drag.js`）。

### 关键实现

| 项 | 做法 |
|---|---|
| 启动阈值 | 5px（WPF 用 `MinimumHorizontalDragDistance`） |
| 换位死区 | `min(16, 邻框宽×0.2)` —— 小页签自动缩小，否则窄页签几乎换不动 |
| 探测点 | 跟随元素**中心** X（不是指针位置，才跟手） |
| 循环推进 | 一次 move 可跨多格，快速甩动追得上 |
| 自动滚动 | 贴边 56px 区，4–18px/帧按侵入深度加速；用 rAF（页面隐藏自动暂停） |
| 取消 | ESC 或落点未变 → 回弹动画（WPF 的 `SpringBack`） |

**滚动后必须主动重算跟随与换位** —— 滚动不产生 `pointermove`，不补算标签会脱手。

**事件委托**：`pointerdown` 挂容器、按 `[data-tab-id]` 找目标，所以
`renderTabs()` 每次重建 DOM 都不会累积监听器（原实现是每个页签 wire 一次）。

**拖拽结束吞掉这一次 click**，否则松手会顺带触发「切换画布」。

**顺序归并兜底**：重排后若数量对不上就重建、DOM 里漏掉的补到末尾 ——
绝不能静默丢画布。

## 第 10 批：审查修复 + A65/A66 + A5 + A18 + A70 + A71

### 审查抓出的两个真 bug（都是上一批自己引入的）

**1. `exportPdf` 误报成功。** `saveBlob` 有 `ok/cancel/fallback/error` 四种返回，
其余 7 处导出函数都用 `reportSave(r, what)` 正确处理了，
只有 `exportPdf` 写成 `if (r !== 'cancel') 就报成功` ——
**`error` 也会落进那个分支**，于是保存失败却提示「已导出 PDF」。

**2. 主题导入未校验颜色值。** A64（新建主题以当前为种子）里早就发现
`sub='transparent'` 写进 palette 会让**整个主题失效**，当时做了回落；
但**导入路径完全没有这层校验**。导入一个含非法色值/0 或负数的 JSON，
主题会**静默失效**（画布停在一片错色，用户不知道是导入的锅）。

> **教训（已写进计划）**：这两条都是「同一件事有两条代码路径、只修了一条」。
> 后面遇到双路径（新建/导入、矢量/对话框）都要检查两边是否对称。

### A65/A66 主题导入导出边界

`sanitizePalette()` 是纯函数，处理三类会让主题**静默坏掉**的值：

| 值 | 后果 | 处理 |
|---|---|---|
| `subBackground: 'transparent'` | core 不认 → 整个主题失效 | 回落到画布底色（视觉一致） |
| 任意非法色值 | 同上 | 兜底色 |
| `connectWidth: 0` / 负数 | 连线看不见 / core 崩溃 | 修正为 2 |
| 字号 0 / 负数 | 文字消失 | 修正为默认 |

被修正的字段**必须列出来告诉用户** —— 静默改掉用户文件里的值不合适。

导入重名时加 `(2)(3)` 后缀而不是弹框问「是否覆盖」：
id 是新生成的，重名不会覆盖，只是**看不出区别**；而覆盖会让用户丢掉原来那个。

### A5 剪贴板位图导入

走 `paste` 事件而不是 `navigator.clipboard.read()` —— 后者要授权、
在 WebView2 里常被拒；前者是用户主动 Ctrl+V 的自然结果。

三个关键点：
- 监听挂 **document**（paste 只派发给焦点元素，对话框本身拿不到焦点）
- **关闭时必须解绑** —— 不解绑会重复触发，一次 Ctrl+V 加进去两份图标
- 只认图片；剪贴板没图就**静默不响应**（否则每按一次 Ctrl+V 都弹提示很烦）

### A18 失效图标清理

C# 版判断「磁盘文件还在不在」；Web 版没有磁盘文件，等价物是
**IndexedDB 里的资产记录** —— 图标条目还在但资产读不出来，就是失效。
典型场景：清过浏览器数据、跨设备导入配置、资产写入半途失败。

失效图标在界面上就是**一块空白**，和之前踩过的「深色界面上纯黑 = 看不见」
是同一类问题：用户只看到一堆占位，不知道是图标坏了还是加载慢。

### A70 开发者工具

Rust 侧 `mm_open_devtools`（前端无权开控制台）。
**release 构建明确报错**而不是静默失败 —— 给最终用户开控制台没有意义。

### A71 诊断捕获

kityminder 跑在**嵌套 iframe** 里，那边的报错**不会出现在外壳控制台** ——
除非特意打开 iframe 的开发者工具。于是「点了没反应」「画布空白」这类问题
在用户侧完全没有线索可查。

- iframe 侧捕获 `onerror` / `unhandledrejection` / `console.error|warn`，postMessage 上报
- 资源加载错误要用**捕获阶段**（那类不冒泡）
- 外壳侧也捕获一份 —— 少了这半边，插件层抛的异常同样没线索
- 环形缓冲保留最近 100 条，**丢最旧的**（诊断看的是「刚刚发生了什么」）
- 展示用只读 `textarea` 而非 `<pre>`：要能整段复制去报问题

## 第 12 批：A29 搜索状态三态 + B22 跨机迁移提示（最后 2 项打磨）

### A29 搜索失败状态

搜索框原先把三种情况**统一显示「无匹配」**：

| 情况 | 修复前 | 修复后 |
|---|---|---|
| 没输入关键字 | 无匹配 | **请输入关键字** ⚠ |
| 编辑器未就绪 | 无匹配 | **编辑器未就绪** ⚠ |
| 搜索出错 | 无匹配 | **搜索失败** ⚠ |
| 真的没搜到 | 无匹配 | 无匹配（正常，不报警） |

**「编辑器未就绪」这一种最误导** —— 用户刚打开画布还在加载时搜索，
看到「无匹配」会以为自己的脑图里真没有那个词。

根因在 `EditorBridge.search()` 的兜底：
`_safe(...) || { total: 0, index: 0, text: '' }` 把「未就绪」和「搜了没结果」
**压成了同一个结果**。改成 `ok:false + reason` 后三态才分得开。

### B22 附件跨机迁移提示

本插件的 `.json` 只存引用，附件本体在 IndexedDB。换台机器导入后，
**引用看着正常、附件图标也在，但字节没跟过来**。

必须在**导入成功后立刻**提示，不能等用户点到那个节点才发现 ——
那时他已经以为文件坏了。提示要说清**为什么**（只带引用不带本体）
和**怎么办**（改用 .xmind，它会把附件打包）。

只针对 .json；.xmind 本来就带附件，不在那条分支调用。

## 多附件（一个节点可挂多个文件 / 视频 / 图片）

`file` / `video` 字段现在是 **JSON 数组串**，`images` 存 dataURL 数组。
一次拖 3 个文件 → 全部挂在同一个节点上，向下依次排开。

| 类型 | 画布上的呈现 |
|---|---|
| 图片 | **横幅**：多张可左右切换，带「i/n」计数 |
| 视频 | 一张卡片 + 右上角**数字角标**（显示总数） |
| 文件 | 每行一个（图标 + 文件名），行距 17px |

### 三个必须守住的边界

**1. 写一定是数组，读两者都认。**
老数据（C# 版迁移、旧 Web 版）是单个对象串或纯路径串，读取时包成单元素数组。
`io.decodeRefList` 与编辑器里的 `refListOf` 是**两份实现**（编辑器是独立 HTML，
import 不了 io.js），测试里逐例比对两边结果 —— 改一边忘另一边会立刻红。

**2. 单张图走 `image`（内核渲染，框内），≥2 张才走 `images`（横幅）。**
两个字段同时有值会让同一个节点画出两张图。所以 `ImagesCommand` 在切模式时
必须清掉另一个，而 `imageListOf` **只读 `images`**。

代价：1→2 张时图片位置会从框内挪到框外。换来的是两套逻辑永不重复渲染。

**3. 视频角标数字用深色 `#1B1B1F`。**
角标圆底跟随节点文字色（可能是浅色），数字若也跟随节点色，在浅色主题上就看不见了。

### 视频首帧缩略图

存在 `ref.t` 里而不是查询时生成 —— 画布渲染是**同步**的，查 IndexedDB 来不及。
几 KB，随 .xmind 一并导出。生成失败一律返回 null（缩略图不能挡住附加本身），
并带 4 秒超时（某些编码元数据加载很慢）。

`src` 必须带 `#t=0.1`：不 seek 的话不少浏览器不绘制首帧，抓出来是全黑。

### 审查（功能 → 显示）后补的三处

**1. 点画布上的图片会误报「旧版本地路径」。**
图片是 dataURL，`openAttachment` 里的 `decodeRef` 会把它兜底成
`legacyPath`（`a` 为 null），于是走进"旧版路径打不开"分支。
现在 `onOpenAttach` 对 `kind === 'image'` 单独走 `openPreview`。

**2. XMind 导入的附件写回时机。**
`out[idx]` 在 `saveAsset` resolve 前还是**占位值**（包内路径）。
若在 `await Promise.all(tasks)` 之前就 `JSON.stringify(out)` 写回，
引用会被固化成 `resources/kma_0_…` —— 导出再导入后**所有附件都打不开**。
必须等全部 resolve 再写回（`pending` 队列）。

**3. 侧栏"详情区显示第几个"的索引。**
写成 `pageFile` 内的局部变量的话，`refresh()` 重建 DOM 时每次都归 0 ——
点第 3 个文件想看它的详情，刷新完又跳回第 1 个，表现为"点了没反应"。
必须提到模块级。另外选中行要有高亮，否则用户不知道自己选的是哪一行。

### 覆盖提示设置项已取消

原来是"单值字段被顶掉"才需要提示；现在一律是**追加**，没有覆盖场景了。

## 拖放附加（图片 / 视频 / 文件）

把文件拖到节点上即附加，省去「选中 → 侧栏翻页 → 点按钮」。

| 拖到 | 行为 |
|---|---|
| **节点上** | 第 1 个挂该节点；其余各建一个子节点（名字取文件名主干） |
| **空白处** | 忽略，不建节点，但会提示 |

**空白处不建节点**是刻意的：拖放容错差，误建的空白节点清理起来很烦。
但必须提示，否则用户只会觉得"拖了没反应"。

分类：图片内联成 dataURL（随 .xmind 一起导出）；视频 / 其它文件进 IndexedDB 资产库。

### 三个实测约束（不是风格选择）

1. **`dragover` 必须 `preventDefault()`** —— 否则浏览器根本不派发 `drop`（默认行为是"打开文件"，会直接跳转走）
2. **原生拖拽期间不派发 `mousemove`** —— 拿不到"当前悬停节点"，只能从 `drop` 的 `target` 反查 DOM。
   内核的 `rc.minderNode` 挂在 kity Group 对象上，DOM 上反查不到，所以另建 DOM → node 映射
3. **映射必须用 `WeakMap`** —— 画布重渲极其频繁，普通 `Map` 会稳定泄漏

### 覆盖提示（设置项）

图片 / 视频 / 文件在单个节点上都只能有一个，挂第二个会**静默顶掉**第一个，不可逆。
所以默认弹确认，设置里可关（`settings.confirmDropOverwrite`，默认开）。

取消只跳过**那一个**文件，不中断整批 —— 拖 5 个取消第 1 个，后面 4 个照常处理。

### 一个隐蔽的坑：每轮都要重新锁定目标节点

存资产要写 IndexedDB，是**异步**的。期间用户可能点了别处、选中态就变了，
第二个文件会挂到错误节点上。所以循环里**每处理一个文件前**都调一次
`bridge.selectNodeById(nodeId)`，不能只在第一轮锁。

（这个坑是靠变异验证发现的：把 `if (nodeId)` 改成 `if (i === 0 && nodeId)`
源码断言照样绿 —— 必须显式禁止"只在首轮锁"的写法。）

## 画布附件名文字标签

**WPF 原版与早前的 Web 版都只画图标、不画文件名** ——
用户问「是不是 bug」时核对过两侧源码（`KityMinderPlugin/Assets/kityminder/index.html:147-215`
与本文件），确认是**功能缺失**：只画了图标，名字压根没画过。
（我后来加的 `<title>` 只是浏览器原生悬浮提示，要鼠标停一会儿才出，多数人不会发现。）

现在在节点框**正下方**画一行小字：居中、节点文字色、字号 = 节点字号 × 0.75 并钳在 [9,13]。

几个决定：

1. **老式路径要显示文件名。** `refName` 原先只解 JSON，遇到 C# 版留下的纯路径
   字符串返回空、只能显示「文件附件」。现在兜底取路径末段，老文件也认得出。
2. **长名必须截断**（14 字 + 省略号）：不截会横穿整张图、压住别的分支。
3. **`pointer-events: none`**：文字比图标宽得多，可点击会挡住画布拖拽
   与空白处框选，得不偿失。点图标本身照样能打开文件。
4. **重渲必须回收旧标签**（`_kmLabels`）：不回收的话节点每次重画都叠一层，越叠越黑。

位置说明：图标画在节点**右侧**、垂直居中（`box.right` 起、`y = box.cy`）；
名字标签只用 `box.bottom` 与 `box.cx`，不依赖 `cy`。所以若观察到
「名字位置对、图标位置偏下」，问题就出在 `cy` 上，与标签无关。

## 第 13 批：多格式互转（FreeMind / OPML / Mermaid / PlantUML）

新增 `formats.js`，让脑图能和市面主流工具交换文件。

| 格式 | 扩展名 | 代表软件 |
|---|---|---|
| **FreeMind** | `.mm` | FreeMind、Freeplane、XMind（可导入）、Docear、MindMeister |
| **OPML** | `.opml` | OmniOutliner、Scrivener、Workflowy、幕布、多数大纲/阅读器 |
| **Mermaid** | `.mmd` | GitHub、GitLab、Notion、Obsidian 原生渲染 |
| **PlantUML** | `.puml` | PlantUML、Confluence、多数 Wiki |

### 一个必须说清的限制：这些都是**单画布**格式

顶层结构都只有一个根，装不下多画布工作簿。所以：

- **导出**只写当前激活画布，并在状态栏明确说明（用户有 3 张画布时静默只导 1 张，会以为另外 2 张丢了）
- **导入**产生一张新画布，用**文件名**当标题（否则连导几张全是「画布 1」，分不清）

需要多画布请用 `.xmind` 或本工具 `.json`。

### 只交换「文字 + 层级 + 折叠状态」

这些格式承载不了图标、优先级、进度、附件。硬塞进自定义属性只会在别的软件里变乱码，一律不写。

### 几个容易踩的点

**1. `escXml` 里 `&` 必须第一个替换。** 否则会把刚生成的 `&amp;` 里的 & 又转义一遍，变成 `&amp;amp;`。

**2. Mermaid 的 id 剥离不能用简单正则。** 初版写 `/^[A-Za-z_][\w-]*\s*/`，结果
`B`、`plan` 这类**纯文字节点被整条当成 id 吃掉**，回环测试里 B / B1 两个节点凭空消失。
必须要求 id 后紧跟 `[` `(` `{`（正向前瞻断言）。

**3. Mermaid 节点文字含 `()` `[]` `#` 等必须加引号**，否则整张图解析失败一片空白；
空节点也要占位成 `""`，否则同样报错。

**4. OPML 允许多个顶层 outline，kityminder 只能有一个 root。** 多个顶层时
**造一个虚拟根**把它们挂上去 —— 不造的话除第一个以外会被静默丢掉。

**5. 格式识别必须「内容优先于扩展名」。** 用户常把 `.opml` 存成 `.xml`、
`.mmd` 存成 `.txt`，而 `.mm` 既是 FreeMind 也可能是别人导出的 Markdown。只认扩展名会大面积误判。

**6. XML 解析走 `DOMParser` 而非正则。** 正则碰上 `TEXT="a>b"`、属性值里带 `>`、
多行文本都会解析错，这类输入在真实文件里并不罕见。注意 DOMParser 解析失败时
返回 `<parsererror>` 文档而**不抛异常**，必须显式检查。

## P3：打印 / PDF（A34–A37 / A41 / B29）—— **不是移植项**

### 开工前核实：WPF 原版没有打印功能

清单里这六项的出处**全部写着「未定位到确切行号」**。核实结果：WPF 全仓搜
`Print` **零命中** —— 没有任何文档打印代码。唯一命中的 `PrintWindow` 在
`ScreenCaptureService` 里，是**截窗口的 Win32 API**，与文档打印毫无关系。

所以这不是「从 WPF 漏移植」，而是**未经核实的推测**（与 B2/B3 剪贴板同类
误判：先入为主地以为「桌面应用应该有 X」）。已改判为 **Web 版新增能力**。

### 技术路线：默认 **svg2pdf（矢量、静默）**，打印对话框作托底

**默认走 svg2pdf —— 不经浏览器、不弹对话框、直接保存。**
这是本轮相比初版的重要修正：初版把 SVG 塞进 HTML 再交给 webview 打印，
等于让矢量图绕了一圈浏览器，还把 wry 的平台缺陷一并引进来了。

#### 为什么 svg2pdf 是对的

kityminder 导出的**本身就是 SVG**，SVG → PDF 是矢量到矢量的直接转换，
不需要浏览器参与。且经核实它只用到 path / text / image，
不含 gradient / pattern / clipPath / filter / foreignObject，
全在 svg2pdf 能力范围内（详见仓库根 `打印与PDF方案对比.md`）。

#### 双通道与托底

| settings.pdfChannel | 先试 | 失败时 |
|---|---|---|
| `vector`（**默认**） | svg2pdf，静默落盘 | **自动**转打印对话框 + 明确提示 |
| `dialog` | 打印对话框 | — |

两条路互为托底，**用户不必每次选** —— 设置里那个下拉选的是「先试哪条」，
不是硬切换。设置项的存在是为了满足确实想要对话框的用户，
而不是把选择成本转嫁给所有人。

**托底时必须明确提示**：静默导出中途突然弹出打印对话框会让人困惑，
所以状态栏会说明「矢量 PDF 不可用，改用打印对话框：原因」。

#### 已知限制

- **Linux 中文字体**：字体族写死 `Arial, "Microsoft YaHei","Heiti SC"`。
  Windows / macOS 都有，Linux 可能缺失导致中文走形。
  完整覆盖需内置开源中文字体，体积代价大，暂不做。
- **单页**：svg2pdf 生成单页 PDF，页面尺寸按 A4 内容区等比缩放（只缩不放）。
  多画布合成多页 PDF 尚未实现（可用 `to_chunk` 拼装，留给后续）。

#### 为什么仍保留 `mm_print`

`WebviewWindow::print()` 在 **wry 只在 macOS 实现**，Windows / Linux 是 no-op
（不弹窗也不报错）。所以它只在 macOS 上真正走原生；其它平台回退
`window.print()`。保留它的价值是作为**通用兜底**——打印对话框几乎总能出结果。

按你的要求改走 **Tauri Rust 命令 `mm_print`**（`src-tauri/src/main.rs`）。

**但有个必须知道的前提**：Tauri 官方文档（含最新 2.4.1）在
`WebviewWindow::print()` 上明确写着 ——

> "Currently only supported on macOS on wry. window.print() works on all platforms."

即 **wry 只在 macOS 实现了原生打印**，Windows / Linux 上是 **no-op**：
不弹窗、也不报错。这比直接失败更难排查 —— 用户只看到「点了打印没反应」。

所以 Rust 侧**主动声明支持范围**，而不是让它静默失败：

| 平台 | 行为 |
|---|---|
| macOS | 调原生打印（`NSPrintOperation`），返回 `"native"` |
| Windows / Linux | **返回 Err**，前端回退 `window.print()` |

前端两条路都走：先 `ctx.invoke('mm_print')`，reject 就回退。这样
跨平台行为可预测，将来 wry 补齐别的平台只要放开 cfg 就行。

另外：浏览器调试模式下 `ctx.invoke` 会直接 reject（不在 Tauri 环境），
同样走回退 —— 所以 `npm run dev` 里也能正常打印。

**静默导出 PDF 仍未实现**：Tauri 2 没有内置 PDF 能力，
`WebviewWindow::print()` 打开的是系统打印对话框，在其中选
「Microsoft Print to PDF / 存为 PDF」导出。若要真正的静默 PDF，
需 `tauri-plugin-printer-v2`（仅 Windows）或 `windows` + `webview2-com`
直接调 WebView2 的 `PrintToPdf` —— 两者都要新增依赖，未擅自引入。

1. 浏览器的打印对话框**自带预览** → 覆盖打印预览需求；
2. 打印目标里通常有「另存为 PDF」→ 覆盖 PDF 导出需求；
3. 不需要写 Rust，风险与维护成本低得多。

代价：无法「静默导出 PDF」，必须由用户在对话框里确认。

### 三个关键实现点

**1. 打印的是完整画布，不是可视视口。**
用 `exportSvg()`（内核 `getRenderBox()`，全图），视口截图印出来只有一角。

**2. `print-color-adjust: exact` 是能看的前提。**
浏览器打印**默认丢弃背景**，深色画布会印成一张白纸，节点底色全没了。
必须带 `-webkit-` 前缀（Safari/Chrome 需要）。

**3. `fitSvgForPrint` 只去掉固定宽高，viewBox 保持不动。**
去掉 width/height 交给 CSS（`width:100%; height:auto`）按纸宽等比缩放；
改掉 viewBox 就变成拉伸变形或留大片空白。另显式指定
`preserveAspectRatio` —— 不同浏览器对「只有 viewBox 没有宽高」的 SVG
默认行为不一致。

### 无打印能力时安静返回 false

`printSvg` 在没有 `window.print`、或调用即抛（某些宿主无打印后端）时
返回 `false`，**不冒泡异常** —— 调用方据此提示「当前环境不支持」，
冒泡上去只会变成一个看不懂的 unhandled rejection。

## P2：导入导出（A30 / A31 / A38 / A39）

开工前先核实，结果 **7 项里有 3 项早已实现**（A32 多画布 Markdown 导出、
A33 整本 XMind 快照、A40 命名时间戳），只剩 4 项真要做。

### A38 高分辨率 PNG（真做了）

内核自带 `exportData('png')` 传更大的尺寸**只是补白**，不是高分辨率 ——
源码里是 `drawImage(img, x, y, a.width, a.height)`，没有缩放。

真正的高分辨率：走 SVG 中间层，**重设 width/height 但 viewBox 保持不动**。
SVG 是矢量，viewBox 不变的前提下放大 width/height，光栅化出来就是更高
的像素密度。若连 viewBox 一起改，就退化成把小图铺到大画布上 —— 图还是糊的，
只是四周多了空白（正是内核那个做法）。

倍率钳到 [1,8]：800×600 配 100 倍要 19GB，浏览器是崩而不是慢。

### A30 整体替换导入：不可逆，必须先确认

导入包会**顶掉当前所有画布**。C# 版 `ApplyWorkbookAsync` 同样无条件替换，
但它至少有撤销栈兜底；这里导入后重置历史（新内容=新基线），**撤销救不回来**。

只在**有画布时**才弹确认 —— 空脑图也弹的话，新建后第一次导入就被拦。
JSON 与 XMind 两条分支都要堵，只堵一条等于没堵。

### A31 识别形态要说出来

`parseWorkbook` 本来就区分三种形态，但**从不告诉用户**，于是拿到一个不像
预期的结果时，根本分不清是文件不对还是解析错了。现在状态栏会报
「识别为：多画布包 / 单画布 / Markdown（走了兜底）」。

### A39 导出格式菜单

原先「导出」按钮直接导出 JSON，但按钮上写的是「导出」而不是「导出 JSON」——
点了才知道出来什么格式。改成菜单（左键右键都能开），含 PNG 1/2/3 倍。

## P1：附件与视频（A15–A24 / B20 / B23 / B24）

一次改造，10 项 —— 它们全在「附件信息卡」这一个容器里，分 10 次做等于
把同一个组件重写 10 遍。

### A23 替换 / 移除前确认

对照 WPF `OnFileClick`（:427）/ `OnVideoClick`（:458）。

**不阻断、但也不静默**：C# 版弹的是「移除 or 取消（取消=继续选文件替换）」，
两个选项都指向同一个结果，用户读完反而不确定点了会怎样。改成直白的
「继续替换 / 取消」。关键是不能静默覆盖 —— 已挂着的附件被顶掉是不可逆的，
用户若不知道原来的存在，就分不清「替换成功」和「附件丢了」。

移除同样要先确认，且**取消则真的不删**（不是「问了也照删」）。

顺带把 `window.confirm` 换成 `confirmDialog`：前者长相由浏览器决定、
在深色面板上是个突兀白框，且**无法测试**（jsdom 未实现，返回 undefined）。

### A16 失效仍展示已知字段

对照 WPF `LoadFileIntoPanel`（:552-557）。原版在文件被移动/删除时**照样**
列出类型与所在目录，理由是「方便定位是哪个附件失效」—— 只写一句「打不开」，
用户连是哪个文件都不知道。

### A17 创建时间：Web 版没有真实 ctime

沙箱里的文件是附加时存进来的副本，操作系统的 ctime 无从取得。最接近的
语义是**添加时间**（`addedAt`）。原文件在磁盘上的创建时间拿不到，
硬凑一个不存在的值不如写明它是什么。

### A19 自动播放策略

原版 `OnOpenFileRequested` 传 `autoplayVideo: true`（:483-491），而**附加**
文件后传 `false`（:446/:477）—— 点了节点图标才自动播，刚选完文件不播。
理由：附加时用户还在整理素材，突然出声很干扰；主动点开才是明确的播放意图。

### A20 进度条 / A21 播放状态

原生 `controls` 在 276px 侧栏里会被挤成一条，几个按钮叠在一起几乎点不中，
所以单独给一条可拖拽的时间轴。时长为 `NaN`（元数据未解析）或 `Infinity`
（直播流）时禁用 —— 否则拖到 Infinity 会让滑块行为诡异。

拖拽期间要**锁定**回写，否则 `timeupdate` 持续回调会让滑块跟手指打架。

状态由**元素事件**驱动，不是在 `start()` 里直接写「播放中」——
`play()` 可能被浏览器策略拒绝，此时并没有真的在播。

### A15 「默认程序打开」不可照搬

WPF 那句 `Process.Start(UseShellExecute=true)` 在浏览器里不成立：拿不到
系统关联程序，也不能对沙箱内的 Blob 调 ShellExecute。落地成「导出到下载
目录」，与 C# 版的差距只在最后一步需要手动双击，且必须**说出来**。

## P0：主题与备份（A62 / A64 / A67 / A47 / A42）

### A62 主题删除回退（修 bug）

对照 WPF `OnDeleteThemeClick`（`MindMapPanel.xaml.cs:2825`）。

删的若是**正在使用**的主题，必须先切回内置并落盘，否则 `sheet.theme`

用的主题，也会把当前主题重置掉。这里改成只有删的是当前主题才回退。

保存失败时回滚（切回原主题、恢复列表），别把用户卡在「主题已删、切换失败」

### A64 新建主题以当前主题为种子

对照 WPF `OnNewThemeClick`（`MindMapPanel.xaml.cs:2859`）：原版**始终**以
当前选中主题为起点。Web 版原先永远从 `blankTheme()` 起，等于每次新建都要

`themeSeed(themeValue, customThemes)`：自定义主题克隆 palette；内置主题用

色值，直接写进 palette 会让 core 解析失败、整个主题失效。视觉上等价（透出

### A67 按既有序注册全部自定义主题

原先只注册当前画布用的那一个。core 的主题表在编辑器实例内存活，切换画布

顺序固定为 `customThemes` 数组序（core 用注册序做主题解析）。
逐个注册且**不因单个失败中断**：一个坏主题不该连累其它所有主题。

### A47 备份暂停 / 恢复

`backupPaused` 是**临时**停、保留原间隔值；`backupMinutes=0` 是**永久关闭**。

两者必须分开：若用「置 0」来暂停，恢复时用户得重新想起原来设的几分钟。

### A42 备份迁移：导出/导入文件（不是「备份目录」）

C# 版 `MoveMindMapBackupDir` 改的是**文件系统目录**
（`MainViewModel.MindMap.cs:75-98`）。Web 版用 IndexedDB，用户根本看不到
文件，做个「虚拟目录名」既不可见也没人用。

真正等价的诉求是**换机器时能把备份带走** —— 所以落地成导出/导入文件，
这也是 WPF 那个目录的实际用途（拷到别的盘 / 别的机器）。

导入用**合并**而非整体替换：C# 的 Move 是移动（旧的没了），但那是同盘搬迁；
跨机导入若是替换，一旦选错文件就把本机现有快照全清了 —— 不可逆。
合并按 ts 去重；缺 ts 的跳过（否则列表里会出现时间戳为 undefined 的条目）。

导出结束后统一 `trimBackups()` 一次，逐份清理会删掉刚写进去的。

## 预设图标库（A3–A10）

新增 `preset-icons.js`，对应 WPF `PresetIconService`。标签页「图标库…」打开：
左分组、右图标网格（4 列，对齐 WPF），点图标即设为选中节点的图片。

### 与 C# 版的三处刻意差异

1. **图标用 SVG path，不做 .ico 转换（A10 不适用）。**
   C# 存磁盘 `preseticons/<名>.ico` 并靠 `IconConversion` 做多尺寸转换。
   Web 端没有 .ico 编码的必要 —— SVG 天然无损缩放，还能直接当 URL 用。

2. **内置图标不进持久化。**
   只有用户分组落 IndexedDB，内置集合每次从代码生成后拼在最前。否则将来
   新增内置图标，老用户永远看不到（他们库里已「存过」一份旧集合）。

3. **分组约束放宽：内置分组恒在，用户分组可以删光。**
   WPF 是「至少保留一个分组」（`DeleteGroup`），因为删光了库就空了；
   Web 版内置分组兜底，库不会空。

内置：**状态 / 标记 / 方向 / 形状 / 物件** 5 组 23 个图标。
不用 emoji —— 渲染依赖系统字体，换设备可能变豆腐块，而图标是要进导出文件的。

### 一个必须注意的坑：SVG 里不能用 currentColor

图标以 `data:image/svg+xml` 当 `<img>` 加载，此时 SVG 是**独立文档**，
没有继承上下文，`currentColor` 会解析成黑色 —— 深色画布上就是一块看不见
的黑块（与之前附件图标踩过的坑同类）。默认色必须是具体色值。

### 存储口径

- 用户图标本体存 IndexedDB（`asset:*`），不重复占空间；
- 应用到节点时转成 dataURL 内联进脑图 —— 与现有「浏览图片」路径一致
  （内核 `image` 命令只认 URL）；
- 代价是脑图文件会变大，与已有的图片行为口径相同。

## 持久化可靠性（A49 / A48 / A44 / A46）

对照 WPF `SwitchSheetAsync`（`MindMapPanel.xaml.cs:1239-1273`）与
`DelayThenClearSuppressAsync`（`:1850-1861`）补齐的四项。

### A49 切换画布的原子性

`switchSheet()` 在改 `activeId` **之前**必须过四道检查，顺序本身就是原子性：

1. **重入守卫**（WPF `_switchingSheet`）—— 连点两个页签会让两次切换交错：
   第二次进来时 `activeId` 已被第一次改掉，它的 `capture()` 就把当前编辑器
   内容写到**第一张**画布上。
2. **编辑器就绪检查** —— 未就绪时 `exportJson()` 拿不到内容，继续切换就丢
   当前画布的编辑。
3. **目标存在性检查** —— `sheet()` 的 fallback 是 `sheets[0]`，少了这道检查，
   切到不存在的 id 会把当前内容盖到第一张画布上。
4. **`capture()` 返回 `missing` 时必须中止** —— `activeId` 一旦改掉，
   当前画布的编辑就再也回不来了。

守卫用 `try/finally` 释放，异常时不会永久卡死切换。

`capture()` 因此从「返回 boolean」改为**三态**：
`'missing'` / `'same'` / `'changed'`。返回 `false` 无法区分「内容没变」和
「拿不到内容」，而这两者对调用方意义完全相反。

### A48 保存抑制与补存

`suppress` 原先是同步开关，`importJson()` 之后内核还会异步派发
`layoutallfinish` / `selectionchange`，其中任何一个触发 `contentchange`
都会被当成用户编辑。现在改为**延迟解除**（800ms，WPF 是 1200ms ——
它走 WebView2 异步 postMessage，Web 版同源同步直调，不需要那么久）。

关键：**抑制期间不能只丢弃变更**。这期间也可能有真实的用户编辑（切换画布后
立刻打字），吞掉就是永久丢失。故 `onDirty` 在抑制期间记 `dirtyDuringSuppress`，
解除后补存 —— 对应 WPF 的 `_dirtyDuringSuppress`。

### A44 手动备份去重

`backupNow()` 原先无条件写快照。连点几次「立即备份」就产生一堆内容相同的
快照，而保留份数有限（默认 10），这些空快照会把**真实的历史版本挤出去** ——
恰好在最需要回滚时找不到可用版本。现在与自动备份路径一致：先比指纹。
`force=true` 可强制写（恢复前的自动留档用它）。

### A46 从快照恢复

恢复会覆盖**当前所有画布**且不可逆，现在有两道保护：

1. UI 层 `window.confirm()` 确认，文案说明不可撤销；
2. 恢复前先把当前状态另存一份快照 —— 恢复错了（选错时间点）还能再回滚。
   这份是最新的，不会被滚动删除。

## 主题配色条

每个主题原来只有一个圆点（根节点色），看不出画布底色和各级节点长什么样。
现在改成**四段配色条**：画布底 / 根节点 / 主节点 / 子节点。

四色全部取自 `kityminder.core.min.js` 的真实主题定义：

| 主题族 | 取值 |
|---|---|
| `fresh-*` | 内核用 HSL 生成：root = `H(h,37%,60%)`、main = `H(h,33%,95%)`，色相 `{red:0, soil:25, green:122, blue:204, purple:246, pink:334}` |
| `classic` / `snow` / `fish` | root `#E9DF98`、main `#A4C5C0`，直接读自源码 |
| `wire` | 无节点背景（`stroke:none`，只画 `#999` 的线），四色都记 `#999999` |

算出来的 fresh 系列 root 与原先手填的值**完全一致**（`#BF7373` / `#BF9373` /
`#73BF76` / `#73A1BF` / `#7B73BF` / `#BF7394`），两边互为校验 —— 测试里就用
HSL 公式反算一遍锁住。

**为什么必须显示四色而不是只显示 root**：`snow`、`classic`、`fish` 三者的 root
**同为 `#E9DF98`**，只看圆点完全分不出来；它们的差别在 sub（snow/fish 是白色、
classic 是透明）。

条做成**扁长条**（150×10，约 15:1）而不是小方块：每段约 36px 宽，层次一眼
看清；又不至于把列表撑高 —— 十个主题仍在一屏内。

三个细节：

- 子节点 `transparent` 时按**画布底色**显示并加**斜纹**标记。留空白的话会被
  当成「这一项没有颜色」。条只有 10px 高，纹路必须够细密（1px/3px）才看得出来。
- 配色条有外圈描边 —— `snow` / `classic` 的画布底 `#3A4144` 与深色面板太接近，
  没有边就糊在一起。
- **段间有 1px 中灰分隔线**：`wire` 主题四段都是 `#999`，没有分隔就糊成一整条，
  看不出是四段。中灰是安全选择 —— 浅色段上比白深、深色段上比黑浅，两种底都可见。

选中态用 `accent` **外环**而不是内凹阴影：配色条本身是色块，内凹在这上面看不出来。

自定义主题走 `palette` 字段（`background` / `rootBackground` / `mainBackground` /
`subBackground`），字段名与内置主题不同，由 `customSwatch()` 归一。

## 视频预览的三种状态必须分开说

「有引用但读不到本体」和「完全没有附件」是两回事，混在一起就会让人以为
附件凭空消失了 —— 节点上明明挂着（画布图标还在画着），侧栏却说「未附加」。

| 状态 | 显示 |
|---|---|
| 无 `video` 引用 | 未附加视频 |
| 有引用但无资产 id | **旧版本地路径，沙箱内读不到本体**（C# 版遗留 / xmind 未打包本体） |
| 有 id 但读不到 | 读取中… → 视频数据已丢失 |

同理，加载中不能是一块纯黑 —— 那也会被当成「没了」。

## 附件在节点间拖拽移动

点一下附件 = 打开；**按住拖到另一个节点 = 移过去**。文件 / 图片 / 视频都一样。

不用 HTML5 Drag & Drop（与页签拖拽同样的理由）：

1. kity 画的是 SVG 元素，没有 `draggable` 属性
2. **原生拖拽期间不派发 `mousemove`**，拿不到「当前悬停的是哪个节点」
3. 拖影由浏览器绘制，无法自定义

所以用 `mousedown` + document 上的 `mousemove` / `mouseup` 自建状态机。

**死区（6px）是必须的**：没有它，手抖 1px 就被当成拖拽，
于是「点一下打开」永远触发不了。

| 拖到 | 行为 |
|---|---|
| 另一个节点 | 移过去（**先加后删**） |
| 空白处 | 提示「请拖到另一个节点上」（不静默） |
| 自己身上 | 空操作，且**不给高亮**（高亮了像「可以放」，实际不会动） |

### 为什么是先加后删

最坏情况对比：

- **先加后删** → 中途失败 = 重复一份（用户手动删掉就行，**可恢复**）
- 先删后加 → 中途失败 = **丢失**（附件丢不可逆）

### 三个实现要点

- **写回前必须按 nodeId 选中目标节点**。`getSelectedXxx` 读的都是
  「当前选中节点」，不选中就会读写错节点。
- **跟随浮层必须 `pointer-events: none`**。否则 `elementFromPoint`
  命中的是浮层自己，永远找不到目标节点。
- **拖拽结束必须把 `attDrag` 置空**。残留的话下次单击会被当成拖拽
  （只「调用了 attEndDrag」不算清理，要真的 `attDrag = null`）。

## 视频播放：截图 / 设为缩略图

点节点上的视频卡片直接播放。播放区下方两个按钮：

| 按钮 | 作用 |
|---|---|
| **截图** | 把当前画面存成图片下载 |
| **设为缩略图** | 把当前画面写回该视频的引用（`ref.t`），节点卡片立刻换成这张 |

### 三个坑

**1. 有声自动播放会被浏览器阻止。** 点画布上的视频虽是一次用户手势，
但 `postMessage` 是异步的，浮层建好时手势可能已过期 —— 表现为
「点开了但不动」。所以先试有声播放，被拒就转静音并**告诉用户**。

**2. 抓不到画面必须返回 `null`，不能返回空串。**
空串也会被当成有效缩略图画出来，结果是一片全黑，比没有更难判断。

**3. 截图存 `.jpg` 不是 `.png`。** 抓出来的是 JPEG 字节，
存成 `.png` 的话有些看图软件会直接拒绝打开（报「文件已损坏」），
而内容其实没问题 —— 扩展名必须跟实际字节一致。

另外：没有节点上下文时**不显示**「设为缩略图」按钮
（点了没反应比没有按钮更让人困惑）。

## 附件图标为什么曾经是「黑块」

`FileIcon` 的矩形底此前写的是 `fill('transparent')`。

**SVG 1.1 的 `fill` 属性不认 `transparent`** —— 那是 CSS 关键字。
渲染器解析不了就回退成默认填充色：**黑色**。于是文件附件在画布上是
一块 16×20 的纯黑矩形，折角和描边被糊在里面，完全认不出是文件。

有个很能说明问题的现象：**鼠标移上去再移开就正常了**。
因为 `mouseout` 里写的是 `fill('none')`，`none` 是合法值 ——
划一下等于手动把属性改对了。

修法就是统一用 `none`（标准值，所有渲染器都认），注释里也写清了原因。

更进一步：**构造时就给默认色**，不依赖 `paint()` 事后上色。
SVG 图形不显式 `fill` 就是默认 black，只要哪条路径漏了 `paint` 就是黑块。
轮廓与折角也**拆成两条 path** —— 合成一条时填充会把折角那条开放线段
当闭合区域填掉，看不出是「文件」。

## 图片：image 命令改成了自有同步实现

内核的 `image` 命令是**异步**的：先 `new Image()` 加载出宽高，
拿到后才 `setData('image')` / `setData('imageSize')`。实测两个后果：

1. **设完立刻读读不到** —— 面板刷新出来是空的。而侧栏读的是打开面板
   那一刻的快照，于是第二次添加图片时基数还是空的，
   新图把第一张**顶掉了**（这正是"加第二张后什么都不见了"的原因）。
2. **清除也异步** —— 传 `null` 时靠 `src=null` 触发 `onerror` 才生效。
   期间 `images` 已写好、`image` 还没清，两个字段并存 → 节点画出两张图。

所以注册了自有 `imageCommand` **覆盖**内核版本：

- 设置：同步写入（先给 120×120 占位尺寸），真实尺寸异步补上后再 render
- 清除：同步，不等回调
- 异步补尺寸时**校验是否换过图**（`getData('image') !== url` 就跳过），
  否则会把旧图的尺寸写到新图上

另外内核 `ImageRenderer` 是 `if (imageSize) { ... }` ——
**没有 `imageSize` 就完全不画**，所以自己写时必须连尺寸一起给。

## 短文本节点的最小宽度

新建节点（文本为空）或只有一两个字的节点，内核算出来的框非常窄 ——
窄到看着不像一个「节点」，点中也困难。

内核 `TextRenderer` 对空文本用 `[" "]`（一个空格）来测量，
所以宽度就是一个空格宽；单字节点同理。

做法：包装 `TextRenderer.update`，把返回的 box 宽度**钳到下限**
（2 个全角字符，即 `2 × font-size`）。只改宽度不动 x ——
center 渲染器按 box 居中，节点变宽后文本自然还是居中的。

⚠️ **不能**往 `_rendererClasses` 里加新渲染器来"撑宽"：
core 的 `renderNodeBatch` 按 `b[0]` 的渲染器数整体迭代，
根节点与子节点渲染器数不一致时会取到 `undefined` 抛错，
结果是子节点全部堆在画布中心 —— 之前踩过，代价很大。

另外补丁是**幂等**的（`__kmMinWidthPatched` 标记）：
编辑器重复初始化时不会多套一层，否则下限被应用两次、宽度翻倍。

## 图片预览：左右切换 + ← → 快捷键

多张图时会多出一条切换条：`◀  1/3  ▶`，同时支持键盘 ← →。单张时不渲染
（没必要占地方，按钮点了也没反应）。

**切换要连标题一起改。** `i/n` 变了但标题还是第一张的名字，
看着就像切换失败了 —— 所以取浮层里那个 `h3` 同步更新
（改到一个游离元素上是没效果的，这点专门写了断言）。

**关闭时必须解绑键盘监听。** 监听挂在 `document` 上，残留的话会拦住
画布上的 ← → —— 那两个键在 kityminder 里是有用的。

另外：输入框里不抢键；起始下标按点击的那张来（点第 2 张缩略图就从第 2 张开始）。

数据来源：
· 文件页缩略图 —— 本来就有完整数组，直接传
· 点画布上的图 —— 编辑器随消息带上该节点的整组图片；
  只在图片这条路径带（视频/文件本体在 IndexedDB，整包发等于复制一遍文件），
  且只有 1 张时置空（不白拷一次大数组）

## 预览滚轮切换的三个坑

**1. 一次手势只切一张。** 滚轮事件远比按键密集 —— 触控板轻轻一划就是
几十个事件，不处理的话三张图会被瞬间切好几圈。所以触发一次后**上锁**，
等滚轮停下来（90ms 内不再有事件）才解锁。

不用「累积量 ÷ 阈值」那套：惯性滚动的 delta 能攒到几百，
一次滑动会切掉七八张。

**2. 必须 `passive: false`。** wheel 默认按 passive 注册，
此时 `preventDefault()` 会被忽略（浏览器还打警告），
结果是浮层背后的页面跟着一起滚。

**3. 只拦浮层内的滚动。** 监听挂在 `document` 上，不判断 `target`
的话页面正常滚动会被预览浮层劫持。

另：关闭时 `clearTimeout` 并复位状态 —— 定时器留着会在浮层销毁后
还跑一次，访问已移除的 DOM。

## 文件面板：随选中节点实时更新

点另一个节点，文件页要立刻换成那个节点的附件。之前不行 ——
得手动切到别的页签再切回来才更新，因为刷新只发生在 `open()` 里。

改动链：编辑器发 `selchange` → bridge 透传 → 宿主 `onSelectionChange`
→ 只在**当前停在文件页**时 `side.refresh()`。

三个要点：

**1. 必须监听 `selectionclear`。** 只听 `selectionchange` 的话，
取消选中（点空白处）不会通知，面板就停在旧节点的附件上。

**2. 带 nodeId 并在宿主侧去重。** 拖选会连发多次 `selectionchange`，
不判断"是否真的换了节点"就会反复重建 DOM —— 缩略图一直闪。
编辑器侧还加了 60ms 合并（一帧内可能好几次）。

**3. 只刷当前停在文件页的情况。** 别的页切回来时 `open()` 本身会 render，
读的就是最新选中，多刷一次是白费。

另：`notifySelectedStyle` 在**无选中时会直接 return** 不发消息
（那样会把样式面板清成空），所以另发一条独立的 `selchange`，
不能复用它。

## 未选中提示：落在空列表处，不整页替换

原先未选中节点时**整页替换**成一句话，按钮全没了 —— 面板像坏了。
现在改成只把「文件」那一栏的空提示换成引导语，视频/图片两栏仍显示
各自的空提示（三栏都换的话同一句话重复三遍，看着很像 bug）。

按钮照常保留：提示是提示，不该把操作入口一起干掉。

## 侧栏内容全部居中：CSS 层叠导致的（.mm-field）

现象：右侧面板内容整片水平居中。

根因是**同名类在两个样式表里语义不同**：

· `../../css/controls.css`（共享控件样式，先加载）里
  `.mm-field` 是「横向排一行的控件组」：`display:flex; align-items:center`
· 本插件 `styles.css`（后加载）里 `.mm-field` 是**纵向**的：
  label 在上、控件在下

CSS 是层叠的：本文件只覆盖**写出来**的属性。这里改了 `flex-direction: column`
却没写 `align-items`，那个 `center` 就原样保留 ——
**纵向排列 + 水平居中 = 面板内容全居中**。

默认值 `stretch` 救不了：controls.css 那条规则特异性相同、位置在前，
只有**显式声明**才能盖掉。所以必须写明 `align-items: stretch`。

通用防线：凡是本插件改了 `flex-direction` 却没写 `align-items` 的纵向容器，
只要类名也被 controls.css 定义，就会被层叠成居中。测试里有自动扫描，
新增这类容器会立刻报出来。

## 侧栏「导入导出」页

界面上**所有**导入导出入口集中在这一页。原先分散在四处，而且同一件事
在不同入口能点到的格式还不一样 —— 用户不知道去哪儿找某个格式：

| 原位置 | 原有入口 |
|---|---|
| 顶栏 | 导入 / 导出▾（全套）/ XMIND / TXT / MD / SVG / PNG |
| 文件页 | 导出 JSON / 导出 MD / 导入… |
| 主题页 | 导入主题 / 导出主题 |
| 设置 · 备份 | 导出全部 / 从文件导入（快照） |

现在顶栏只留画布级操作（新建 / 复制）；`openExportMenu`（顶栏下拉菜单）
一并删除 —— 留着就是死代码，而且会让入口继续分裂成两处。

页内分六节：导入 / 导出为文档 / 导出为交换格式 / 导出为图像·PDF /
主题 / 快照备份。

**面板只持有 `app.api`，不直接碰插件内部函数**，所以这些能力都通过 api

两个容易写错的点：

· **交换格式的 kind 不能串** —— Mermaid 的按钮误接成 `'opml'` 也能跑通，
  只是导出格式错了，肉眼看不出来

## 文字垂直居中：改用真实测量，不再吃内核经验系数

症状：**换主题后文字不居中** —— 中央主题、子主题、更下级主题有的偏高、
有的偏低，而且不同主题偏的方向和量都不一样。

**根因**在内核 `TextRenderer.update` 的最后一行：

```js
a.setTranslate(0, (d || 0) * fontSize)
```

`d` 来自一张硬编码的「浏览器 × 平台 × 字体族」经验表（`chrome.Win` 里
`"微软雅黑,Microsoft YaHei": -.15`、`default: -.15` …）。三个前提在
WebView2 里**都不成立**：

1. **主题里根本没有 `font-family`** —— `fresh-*` / classic / snow / fish
   的定义只有 `root/main/sub-font-size` 与 `line-height`，所以取到的
   font-family 恒为 `"default"`，永远只命中那一个经验值
2. **`d` 只乘 font-size，不含行数与行高** —— 多行节点必然偏
3. 该表是按「浏览器 + 微软雅黑 + `dominant-baseline:text-before-edge`
   表示文本顶部」标定的。Chromium 一旦把 `text-before-edge` 当基线处理，
   `setY` 的含义就从「顶部」变成「基线」，整套计算错位

于是字号越大、行数越多，偏差越大 —— 这就是「不同主题表现不同」
（root 字号 16 vs 24）。

**修法：不再猜，直接测。** SVG 的 `getBBox()` **不含元素自身的
transform**，拿到的正是「尚未平移」的真实文本边界，据此把文本中心
对齐到内容盒中心。无论字体、字号、行数、baseline 语义如何，都自动居中。

两个必须守住的边界：

**测不到真实边界时必须返回 `null` 并保持内核落点**，不能设 0 ——
那会把内核的经验补偿整个抹掉，文字反而更偏。

**原实现开头有 `if (!va) return;`**，只有显式设过 `vertical-align`
的节点才被校正。而 Web 版没有任何入口去设这个值（panels.js / index.js
里都没有 valign 命令），所以**它对所有节点都是死的**，三级微调表
`__valignOffset` 也就永远读不到 —— 这正是"原源码做过偏移、现在没生效"
的那一环。现在默认节点也进校正分支，微调表才真正可用。

默认对齐策略：纯文本节点做视觉居中；节点带图片（内容盒明显更高）时
**保留内核的沉底语义**，不改动带图节点的既有布局。

## 样式面板：一排化 / 删除按钮弱化 / 分节清除

**徽章单排 10 格**（1–9 + 清除）。原先是两排 5 列（对齐 WPF
`BuildSpriteNumRow` 的两行），但这是**同一个维度**的 10 个档位，
拆成两排会让人误以为 1–5 与 6–9 是两类东西。

宽度是够的：侧栏 276px − padding 24px = 252px；10 × 20px = 200px，
余 52px 分给 9 个间隙。渲染上用 `space-between` 且 `flex-wrap: nowrap`
—— 写死 gap 一旦算错就溢出换行，而 space-between 是"先保证不换行、
再平分空隙"，徽章变宽时只是间隙被压掉。

**字体色与 B / I / S 同一行**。颜色与字形修饰都是「文字外观」，
拆成两行会让人以为是两组不相干的设置。实现上给 `colorRow` 加了
`extras` 参数，而不是另起一行再塞进去。

**图标区三个按钮同一行**（图标库 / 浏览图片 / 清除）。原先「清除图标」
独占一行，孤零零看着像另一个独立功能。

**圆角归入「节点」节**。「节点填充」与「节点边框」合并为一节，
四组控件（填充 / 描边 / 线宽 / 圆角）本就是「节点长什么样」的同一维度。
该节的清除按钮要同时清 `node`（填充+圆角）与 `border`（描边色+线宽）
两个 scope —— 内核里是两个命令，只清一个会留下半截样式。

**清除按钮挂在节标题右边**，不再在末尾凑成一排四个。四个同名按钮
挤一排时分不清哪个清的是文字、哪个清的是连线；挂标题右边后，
「这个按钮管这一节」由位置直接表达出来。「清除全部」保留在样式刷节里
—— 它与复制/粘贴同为**整体**操作，而各节标题右边的是**分节**操作。

**删除类按钮统一用 `.mm-btn.quiet`**：无底板、无阴影、弱化色，
hover 时才提亮。样式面板里清除类操作很多，全做成常规按钮会让整页
变成一排排实心按钮，主操作（选色 / 选字号 / 选徽章）被淹没。
不能用 danger 红 —— 清除样式可撤销，全页飘红会让用户以为会丢数据。

## 导入导出页：标题右侧圆形问号 + 悬浮说明

六个节（导入 / 导出为文档 / 导出为交换格式 / 导出为图像·PDF / 主题 /
快照备份）的标题右边各有一个圆形 `?`，悬浮显示该节的补充说明。

界面上只留按钮；**保留在界面上的唯一一条**是「⚠ 导入会替换当前所有画布，
且不可撤销」—— 那是会造成数据丢失的警告，藏进悬浮框里就可能被跳过不看。
其余「按内容嗅探格式」「只导当前画布」「PNG 倍率为什么要自己选」这类
"用之前不必知道、想知道时再看"的信息全部收进问号。

### 为什么不用原生 `title`

延迟 1 秒以上、不能换行（长句会拉成一条横贯屏幕的长条）、样式完全
不受控。所以自定义了 `.mm-helptip`，并**必须把原生 title 置空** ——
否则两个提示会同时弹出来。

### 三个必须守住的边界

**提示框挂 `document.body` + `position: fixed`。** 侧栏是
`overflow-y: auto` 的滚动容器，提示框若留在面板里，超出侧栏边界就会被
**裁剪**（表现为只显示一半或干脆看不见）。挂 body 才不受祖先 overflow 影响。
不允许写成"找不到某容器就退回 body"—— 那样在真实环境里会挂回侧栏，
而测试环境里没有侧栏、仍挂 body，断言照样绿（假阴性）。

**默认 `display: none`，不能只降 `opacity`。** 只透明的话它仍占据文档流
且可被点到，会出现"看不见但挡住了下面的按钮"。

**多段说明要分开成多个 `-line` 并加段间分隔。** 挤成一整段会读不出是几条。

### 定位

竖直优先放问号下方，下方空间不够翻到上方，两侧都放不下时取空间较大的
一侧（而不是硬塞回下方被切掉）。水平方向钳在视口内 —— 侧栏贴着窗口
右缘，不钳的话提示框会超出屏幕右边。

`jsdom` 里 `getBoundingClientRect` 全返回 0，此时直接退到 (0,0)，
不能把 top/left 算成负的一大截（真实环境会因为初始值错乱闪一下）。

## 主题的导入 / 导出回归主题页

「导入… / 导出」移到主题页，与「＋ 新建 / 编辑 / 删除」同排；主题页
那句指路 hint（「自定义的导入/导出在侧栏『导入导出』页」）随之删除。

**为什么这是「集中入口」原则的例外**：集中解决的是"同一个导出在不同
地方能点到的格式不一样"。而主题的导入/导出操作的是**主题这个对象**，
和主题列表里的一整排动作（新建 / 应用 / 编辑 / 删除）是连贯的一组。
收进导入导出页后，主题页要靠一句 hint 指路 —— 等于把一组连贯操作
拆成两地，用户得先意识到"主题的导入导出不在这儿"。

**「内置主题无法导出」改由禁用态表达**（`disabled: isBuiltin` + title
说明原因），不再靠文字。让按钮可点、点了再报错，等于把"做不了"这件
事推迟到用户已经付出操作之后才知道。

该信息同时进了「配色主题」标题右边的问号，所以移走文字后信息没丢。

导入导出页的「主题」节一并删除 —— 留着就是两处入口，等于把刚集中的
入口又拆开。

## 顶栏瘦身 / 聚焦中心主题 / 搜索不阻断选中

### 顶栏去掉「新建 / 复制」

页签区自带 ＋ 新建入口，复制是低频操作，占着顶栏最显眼的位置性价比太低。
`addSheet` / `duplicateSheet` **不能跟着删** —— 页签区的 ＋ 与页签右键
菜单还在调用。

### 左侧图标条加「聚焦中心主题」（⌖）

视图移到根节点并选中它。拖远了、缩放乱了时一键回到中心。

**不能让外壳传节点进来** —— 跨 iframe 传不了对象，根节点只能让编辑器
自己取 `km.getRoot()`。所以是编辑器门面上的 `focusRoot()`，不是
`exec('camera', root)`。

`camera` 的动画时长给 **300ms 而不是 0**：0 会瞬移，用户看不出"发生了
什么、移到哪儿了"。另外**先展开根节点** —— 它若是折叠的，视野里根本
没有内容可看。

### 搜索高亮框拦截点击（搜索之后其他节点点不动）

根因：KityMinder 的选中靠 `getTargetNode()`，从事件的 `targetShape`
往上找带 `minderNode` 的容器。搜索高亮框加在 renderContainer 上、画在
节点**之上**且带半透明填充 —— 点它覆盖到的节点时，targetShape 是这个框，
往上找不到 `minderNode`，于是**选不中**。

而且只有取消搜索（`clearSearchMark`）才恢复，现象离根因很远，很难定位。

修法：`shape.setStyle('pointer-events','none')`，并**双保险**直接写
`shape.node.style.pointerEvents` —— 万一 kity 的 setStyle 没落到
node.style 上，拦截依旧发生，而这里写的是浏览器真正认的那一份。

### 选中别的节点后清掉旧高亮框

留着的话画面上会同时出现"选中态"和"搜索高亮"两个框，分不清选中的是哪个。

**必须跳过自己触发的那次**：`focusSearchResult` 里会 `select` 当前匹配
节点，那也会派发 `selectionchange`（且是**同步**的）。不排除的话，刚画
好的框会被自己立刻清掉，等于搜索定位完全没有高亮。

## 布局模板 / 主题的选中态不更新

症状：切换布局模板后画布变了，但面板里选中的还是原来那个。

根因：`sheet` 本身是「取当前画布」的**函数**，而 `app` 对象里写的是
`sheet,`（把函数当属性传出去）。面板里 `app.sheet?.theme` / `?.layout`
读的是**函数对象**上的属性，恒为 `undefined` —— 于是主题与布局的选中态
永远停在默认值。

修法：改成 getter `get sheet() { return sheet(); }`。每次读都拿到当前画布。

这类 bug 的特点：功能"看着能跑"（切布局确实生效），只有**回显**是错的，
所以很容易拖很久才被发现。

## 文件库展开导致画布内容位移：按实测屏幕位置差补偿

### 先纠正一个方法论错误

此前我用"翻遍提交历史没找到那一版"来否定"挤压但内容不动"的观察，
这是**本末倒置**：历史里没有，只说明**没人写过**，不代表那种观感不存在。
正确做法是去查机制、解释观感，而不是用"查无此版"反驳使用者。

实测也推翻了我原来的解释：把内核加载进 jsdom 跑一遍，`_viewDragger`
的运动量**确实变了**（resize 后 `getMovement()` 为 `(-108, 0)`），
说明内核补偿是执行了的。既然机制算不准，就不再推算，改为**直接保证结果**。

### 为什么不能按"固定 Δ 补一半"

Δ 取决于 flex 收缩的分配，不是常量：

```
.mm-files 占位 = flex-basis 186 + padding 10×2 = 206（content-box）
加 .mm-body 的 gap 10  →  216
```

但右侧 `.mm-side` 一旦**可收缩**（历史上它样式失效时正是如此），画布宽度
的变化量就不再等于 216，而随侧栏此刻的内容宽度浮动。此时内核仍机械地补
一半，两者不同源 —— 按固定 Δ/2 硬补就会补错，甚至把原本不动的画面补动。

### 修法：测位置，差多少补多少

编辑器门面：

- `rootScreenX()` —— 中央主题中心的**屏幕** x
  = 容器左边缘屏幕 x + 视图平移 + 根节点 view 盒中心
- `panBy(dx, dy)` → `_viewDragger.move(new kity.Point(dx, dy))`
  （内核没有公开平移命令：`camera` 是把节点移到视口中心、`hand` 是拖拽态、
  `move` 只支持四档固定步长）

外壳 `withStableRoot(fn)`：包住所有会改变底框开合的操作，开合前记下
`rootScreenX`，开合后再测一次，**差多少补多少**。

这样无论中间发生了什么（内核补了几成、侧栏让了多少、有没有重排），
最终落点都是"中央主题没动"。测的是用户实际看到的位置，不是推算值。

要点：

**必须含容器左边缘。** 只测容器内坐标的话，容器自己挪了多少就看不出来，
而"内容动了没有"正是屏幕位置。

**取根节点而非整个内容盒。** 内容盒会随节点增减/重排改变尺寸、中心漂移，
不能当参照物。

**取不到就跳过，不能当 0。** `before`/`after` 为 null 时补一个反向位移，
比不补更糟。

**等两帧而不是一帧。** 一帧只够布局更新，iframe 内的 window resize
（内核据此补位移）也在那一批回调里，早了会测到中间态。

**1px 以内不补** —— 取整噪声，否则每次开合都多一次无谓平移。

**不传 duration**（与内核 resize 一致）：带动画的话两次平移的动画会互相
打断，最终落点不是两者之和。

### 未采纳的 box-sizing 改动

给 `.mm-files` 加 `box-sizing: border-box` 能把占位从 206 降到 186、净位移
从 108 降到 98。但内容区也会从 186 缩到 166（少 20px），文件列表会变窄。
既然位移已经补偿掉了，没必要为此牺牲列表宽度。

### 附带：CSS「规则被截断」检测

历史上出过一次：`.mm-rail { ... }` 被截成只剩 `.mm-rail`（没有 `{ }`），
CSS 解析器继续往后找，把紧跟的注释忽略掉、与下一个选择器拼成
`.mm-rail .mm-side` —— 而 DOM 里 `.mm-side` 不在 `.mm-rail` 内部，
**整套样式静默失效**（表现为"侧栏全居中"）。

`.mm-side` 丢了 `flex: 0 0 276px` 之后就**可收缩**：画布宽度变化量不再是
固定的 216，而取决于侧栏此刻的内容宽度，内核仍机械地补一半 —— 两者不再
同源，位移从"恒定一跳"变成"跟随内容浮动"，这正是"跟随移动"的观感来源。

现有 1859 项断言全是**行为**断言，恰好覆盖不到这种语法级损伤，故新增：

- 形态检测：`选择器独立成行 + 换行 + 注释`（正常写法不会这样）
  —— 不能改成"剥注释后数 token"，那样后代选择器与截断形态剥完注释后
  长得一样，会把 65 条合法规则全判为异常
- 关键属性断言：`.mm-side` 块内 `flex: 0 0 276px` / `display:flex` /
  `overflow-y:auto` / `min-height:0` 均存在

## 保存主题失败：`has only a getter`

### 现象

点「保存主题」报错：

```
Cannot set property customThemes of #<Object> which has only a getter
```

导入主题、删除主题同样是这条路，一并失败。

### 根因

`app` 句柄上 `customThemes` **只有 getter**：

```js
const app = {
  get customThemes() { return customThemes; },   // ← 没有 setter
};
```

而 `panels.js` 有三处 `app.customThemes = ...`（导入 / 删除 / 编辑保存）。
**ES 模块恒为严格模式**，给「只有 getter」的访问器属性赋值会抛 TypeError
（非严格模式下才是静默失败）。已实测复现：

```js
const o = {}; Object.defineProperty(o, 'a', { get: () => 1 });
o.a = 2;   // TypeError: Cannot set property a ... which has only a getter
```

### 修法

补 setter，写回模块级变量（`saveThemes()` 读的就是它）：

```js
get customThemes() { return customThemes; },
set customThemes(v) { customThemes = v || []; },
```

两者缺一不可：getter 让面板读到**当前**值（数组会被整体替换），
setter 让写回真正落到模块级变量。**setter 若写成空实现**，赋值不报错但
`saveThemes()` 存的仍是旧数组 —— 表现为「提示成功，重开又没了」，
比直接抛错更难查，故专门有断言盯着。

### 通用守卫

不能只断言 `customThemes` 一处 —— 下次再加一个 getter-only 的可写状态，
同样的坑会重演，而报错只在运行时出现、测试却全绿。

测试会扫描**所有**拿到 app 句柄的模块，找出 `app.X = ...` 赋值，
逐个要求 `app` 上有对应的 `set X(`。注入 `app.sheet = null`（`sheet` 是
getter-only）已确认能抓到。

## 左侧图标条：两组展开按钮（层级 / 展开）

图标条上有两组各三个按钮，语义差在**基准节点**：

| 组 | 基准 | 用途 |
|---|---|---|
| 层级 | **中心主题**（固定） | 看整幅图的全局视角，跟选中谁无关 |
| 展开 | **当前选中节点** | 围绕这一个节点往外摊开 |

两组必须并存：只有「展开」的话，想看全局还得先去点中心主题，而**没选中
任何节点时它完全没反应**，用户会以为按钮坏了（这正是「层级」独立出来的
原因）；只有「层级」则没法单独摊开某个分支。

编辑器侧两个门面 `expandRootToLevel` / `expandSelectedToLevel`：除取基准
节点那一行（`km.getRoot()` vs `km.getSelectedNode()`）外逐字一致。
测试会断言这一点 —— 否则两组按钮行为会悄悄不一样。

外壳用同一个 `levelGroup()` 生成两组，避免各写一份后只改一组。

## 清除按钮用 ⟲ 而不是 ✕

样式面板里「清除文字 / 节点 / 连线样式」用的是**把样式恢复默认**，不是
关闭。`✕` 在界面上的通行含义是「关闭 / 取消」，用户看到会以为点了就把
这一节收起来，不敢点。改成 `⟲`（还原），与实际行为一致。

## 视频播放区：截图 / 设为缩略图

功能一直在（`openVideo` 里 `grab()` 抓当前帧 → `toDataURL('image/jpeg')`）。
看不见的原因是**布局**：`video.mm-video` 只有 `width: 100%`，竖屏视频
（9:16）按此铺开能到近千像素高，把下方按钮全挤出 `max-height: 86vh` 的
可视区 —— 表现为「按钮不见了」，其实要往下滚才看得到。

修法：给 video 加 `max-height: 54vh` + `object-fit: contain`。
只限高不设 `object-fit` 会把画面压扁。

## 画布文件图标：悬停高亮框与行距

`FileIcon` 的 `rect` 是**悬停高亮框**，几何必须罩住 `outline` 的实际范围
`x∈[-8,3] / y∈[-10,10]`。原先写的是 `(16, 20, 0, -10)` —— 从原点向右延伸
16px，与图标本体**完全错位**，还盖到右边的文件名上。表现为「悬停出现一个
透明小框，位置不对、把文字压住」。改 `(15, 20, -10, -10)`：罩住图标并留
2px 余量，右边界不越过文件名（起点在原点右侧 12px）。

行距原为 17，而图标高 20 → 相邻两行图标**重叠 3px**，即「两个图标叠在
一起」。改 24。

## 数值输入框 numSpinner（▲▼ 步进 / ▾ 选预设 / 滚轮 ±1）

字号 / 线宽 / 圆角三个数值控件统一走 `numSpinner()`，形态是 Windows 经典的
up-down control：

```
[  5  ][ ▲ ][ ▾ ]
       [ ▼ ]
```

三件事分开做，缺一件都会让人以为控件坏了：

| 操作 | 行为 |
|---|---|
| ▲ / ▼ | **±1** |
| ▾ | 弹出预设值列表（粗调） |
| 滚轮 | **±1**（微调） |

### 滚轮是 ±1，不是在预设列表里前后挪

这两者差别很大。圆角预设是 `[0,3,5,8,12,16,24]`，在 3 上滚一下若是"下一个
选项"就跳到 5，而用户期望的是 4 —— **微调靠滚轮，粗调才用列表**。

### 一次手势只走一格

触控板一划就是几十个 wheel 事件，不处理的话数值瞬间冲到上限。触发一次后
**上锁**，静默 `WHEEL_GAP`（90ms）才解锁。与图片预览同一套做法。

只看**方向**不看 delta 大小：惯性滚动的 delta 能攒到几百，按量换算会一次
跳很多格。

### 微调范围必须宽于预设档位

`min` / `max` 不能卡在预设列表的两端 —— 卡住的话微调到最大预设就再也上不
去了，而"比 40 再大一点"这种需求是真的存在的（标题节点）。所以字号是
`MIN_FS=8 / MAX_FS=72`（预设 12–40），圆角上限 40（预设最大 24）。

### 其余边界

- 非法输入（`"abc"`）**不回调**，并还原成当前值 —— 把 NaN 写进节点会让节点
  渲染异常
- 值没变就不回调 —— 免得白记一次撤销
- ↑ / ↓ 键与按钮同义

## 预览滚轮节流：上锁那一行不能漏

`onWheel` 里 `locked` 变量声明了、也检查了，但**从来没有赋值为 `true`** ——
于是"一次手势只切一张"根本没生效，触控板一划连切好几张。

修法是补上 `locked = true;`，并且**上锁期间要把累积量 `acc` 清零**：不清的
话解锁那一刻 acc 已经攒够阈值，会立刻再切一张，表现为"用户停手后画面自己
又跳一下"。

这类 bug 的特点是变量看着都在、逻辑看着也对，只有实测连续事件才暴露。

## 主题：新建 / 编辑后列表立刻刷新

主题列表是在 `pageTheme()` 里按 `app.customThemes` **现算**的，所以保存后
必须重刷侧栏，否则新主题不会出现在列表里，得切走页签再切回来才看得到 ——
用户会以为没保存成功，其实已经落盘了。

宿主暴露 `api.refreshSide`，面板在 `applyTheme` 之后、`dlg.close()` 之前调用。
顺序不能反：提前刷会刷到还没写进 `customThemes` 的旧列表。

## 主题按钮：导入主题 / 导出主题竖排

两个按钮原先挤在一排，被压成「导入…」—— 那个省略号是**被截断**出来的，
不是有意省略，用户得悬停才知道是干什么的。而且一个叫「导入…」一个叫
「导出」，看着像两个不相干的功能。

改名成对（导入主题 / 导出主题）+ 三个按钮竖排 `.mm-col`。侧栏只有 252px
可用，而这几个词没有更短的写法，竖排是唯一选择。

## 附件画进节点框内（节点撑高，不再被相邻节点遮挡）

### 现象

节点上的图片 / 视频 / 文件会被相邻节点盖住。

### 根因

附件原画在节点框**外**（紧贴 contentBox 下沿往下排）。而布局读的是
`node.getContentBox()`（即 `_contentBox`），它由 `_rendererClasses` 里的
渲染器合并得出 —— **画在框外的形状不进这个盒**，布局根本不知道这块占了
地方，于是相邻节点照旧按原尺寸挤在一起，把附件盖住。

### 修法：画在框内 + 撑高 contentBox

在 `noderender` 里按附件区的实际范围重建 `_contentBox`：

```
endY = 附件区下沿 + 内边距
extra = endY - 原盒下沿
w     = max(原盒宽, 附件区宽)
_contentBox = new Box(cx - w/2, 原上沿, w, 原高 + extra)
```

布局随后按撑高后的盒排布，节点之间自然留出空间。

三个要点：

**必须 new 一个 Box，不能改原对象的 height。** `kity.Box` 的
`bottom / cx / cy` 都是构造时算好的**普通属性**（不是 getter），改
`height` 不会连带更新 —— 外框会按旧 bottom 画、连线会按旧 cy 接。

**只往下长，上沿不动。** 正文位置不变，附件排在它下面，视觉上就是
"文字在上、附件在下"的一整块。

**外框必须按新盒重画一次。** 外框渲染器在 `noderender` 之前就跑完了，
不重画的话附件区露在框外 —— 也就是"放进去了但框没跟着变大"。
重画走 `node.getRenderer('OutlineRenderer').update(shape, node, nb)`。
（节点级描边由更晚注册的 `applyNodeStyle` 钩子补回，不会被冲掉。）

### 宽度也要跟着走

节点比附件窄时，图片 / 文件名会横着戳出外框，看着像"没放进去"。
所以附件区宽度取 `max(原盒宽, 附件区宽)`；三类附件各自把自己的宽度
记进 `attW`，漏一类就会戳出去。

文件名宽度只能估算：kity.Text 没有同步可用的 `getWidth()`，量 BBox 又要
等布局完成，而这里在渲染过程中就得算出盒子尺寸。故有 `estTextW()`：
中日韩按 1 个字号、其余按 0.55。**宁可估宽** —— 估窄了会戳出外框，
估宽了只是节点稍宽一点。

### 为什么不往 `_rendererClasses` 里加渲染器撑高

`renderNodeBatch` 按 `b[0]` 的渲染器数整体迭代，各节点渲染器数不一致时
会取到 `undefined`（`Cannot set properties of undefined (setting
'contentBox')`），结果是子节点无法布局、全部堆在画布中心 —— 之前踩过，
代价太大。这里只在 `noderender` 里改 `_contentBox`，不动渲染器数组。

## 导出为交换格式 → 导出为交换格式（单画布）

Freemind / OPML / Mermaid / PlantUML 顶层只有一个根，装不下多画布，
只导当前画布。不写明的话用户会以为多画布都导了，在别的软件里打开发现

## 文件库 / 搜索结果：两个独立页签共用一个底框

两者共用同一个 `.mm-files` 底框（同 186px），但**不是**"搜索时把文件列表
藏起来、取消再放回来"那种替代关系，而是**两个独立页签**：

| 操作 | 结果 |
|---|---|
| 搜索结果出来 | 搜索结果占住底框，文件列表让位 |
| 点 📚 | 切到文件列表，搜索结果被遮盖（仍在内存里） |
| 再点 📚 | 收起文件列表，**退回搜索结果**（不是把底框整个关掉） |
| 清空搜索 | 让位给文件列表（若用户开着），否则底框收起 |
| 无搜索结果时收起文件 | 底框整个收起 |

内部是一个三态：`panel ∈ {'files', 'search', null}`，靠 `apply()` 落到
DOM（底框开合 + 两个 body 互斥 + 标题与按钮随面板切换）。

**为什么不用单个 `searchMode` 布尔**：那是"替代"语义 —— 搜索为真时文件
就是"被藏了"，收起文件后没有地方可退，搜索结果只能随底框一起消失。
三态才能表达"收起一个，底下那个露出来"。

`hasSearch` 与 `panel` 分开：收起搜索面板后 `hasSearch` 仍为 true，
用户再次收起文件时才知道要退回搜索结果。

**标题与「＋ / 📁」随面板切换**：搜索结果页没有"新建脑图"的语义，留着
两个按钮会出现"点了没反应"（它们建的仍是文件，但页面不是文件列表）。

外壳的 `toggleFiles()` 不能再自己按 `settings.filesOpen` 翻转 ——
搜索时文件面板是让位的，但 `settings.filesOpen` 仍可能是 true，
按 settings 算会把状态搞成各说各话。现在由 `fileList.toggleFiles()`
决定，外壳只负责把结果记回 settings。

## 左侧搜索结果面板

搜索时，全部匹配在左侧列出，**复用文件库的底框**（同一个 `.mm-files`
容器、同样 186px 宽），两者互斥显示，所以尺寸天然一致，不用另写一套面板。
点击任意一条即跳转定位到该节点。

编辑器内原先有个 `#search-panel` 浮层（画布左侧浮出），已删除 ——
否则画布上一个、左侧一个，两个结果列表。现在编辑器侧只保留**数据与定位
能力**，渲染交给外壳：

| 编辑器 API | 用途 |
|---|---|
| `getSearchResults()` | 返回 `{kw,total,active,items}`，超过 200 条只回传前 200 条 |
| `gotoSearchResult(idx)` | 定位到第 idx 个（0 起），越界返回 false |

与 `search()` 分开是有意的：`search()` 每调一次就**推进到下一个匹配**，
若让它顺带返回列表，"刷新列表"就会连带多跳一格。

三个必须守住的边界：
· **定位失败要提示**，不能把高亮停在旧项上假装跳过去（内容变化后旧索引会失效）
· **索引越界要返回 false**，否则 `km.select(undefined)` 静默不动，表现为"点了没反应且毫无报错"
· **高亮片段用文本节点构造**，不拼 innerHTML —— 节点文字是用户输入，含标签时拼串就是 XSS

## 布局：文件库是覆盖式抽屉

文件库（含搜索结果）用**绝对定位浮在画布左侧之上**，不参与 flex 流。

原来是 `flex: 0 0 186px` 的 flex 子项，展开会把画布挤窄 196px。代价不只是
"画布变窄"——画布变窄 → 内层 iframe 尺寸变 → iframe 内派发 resize →
kityminder core 的 view 模块监听 resize 并把视图平移 `(新宽-旧宽)/2`
重新居中 → **画布内容在屏幕上左右晃一下**，每次展开/收起都晃。

改成抽屉后画布尺寸完全不变，iframe 不触发 resize，内容一动不动。
只要画布宽度变了，靠"事后反向补偿"是补不干净的 —— 用户拖过画布或缩放过
之后，补偿基准就乱了。

代价：展开时会遮住画布左侧 186px（用更重的阴影压出层次，表明它浮在上层）。

## 控件档位：输入框 / 下拉必须跟按钮同为 28px

`../../css/controls.css` 把 `.mm-input` / `.mm-select` 统一成 38px
（外壳设置页的标准档），而脑图是紧凑布局、按钮一直是 28px。不覆盖的话
顶栏搜索框比旁边按钮高 10px，样式页一排下拉也全比按钮高一截。

用**变量**覆盖（`--ctl-h` 等）而不是直接写 `height`：controls.css 本身就用的
这套变量，改变量才是同一套机制；硬写 height 会和变量打架（谁在后谁赢）。

## 展开层级按钮：移到左侧图标条

原先在右侧栏「样式」页的「视图」节里。那位置很别扭：展开层级是
**看整幅图**的操作，跟「样式（针对选中节点）」不是一类事，而且每次用
都要先切到样式页再往下翻。现在放左侧图标条，常驻可见，一步就到。

右侧栏那一节**整节删掉**，不留空节也不留第二处入口。

两个实现细节：

**按钮宽只有 34px**，所以文字压成「1级 / 2级 / 全」—— 写全「展开一级」
会溢出换行。字号一并收到 11px。

**加分隔线与「层级」小标题。** 图标条原本只有 📚 一个按钮，直接追加三个
等距按钮的话，视觉上是一串，看不出这是另一组操作。

层级值沿用内核约定：**0 = 全部展开**，1 / 2 = 从选中节点展开 N 级（更深层收起）。

## 附件卡片与视频预览（文件页）

早先的形态是「两行文字 + 三个按钮」，文件长什么样完全看不出来，视频也只剩一个
「播放」按钮（点了才弹浮层）。现在改成：

**文件附件** —— 一张卡片：图标（图片则直接显示缩略图）+ 名称 + 大小，点卡片即打开
（图片就地预览，其余只能下载：沙箱拿不到真实路径）。图标按扩展名给，
`🖼 🎬 📕 🗜 📘 📗 📙 🎵 📃 🧩 📄`。

**视频附件** —— 16:9 预览区，默认显示**首帧**，点一下**就地播放**（不再弹浮层）。
下方摘要行给出 名称 · 时长 · 大小。

两个实现细节：

- **`src` 后面要带 `#t=0.1`**。只用 `preload="metadata"` 的话，不少浏览器不 seek
  就不绘制首帧，预览区是一片黑。`preload` 仍是 metadata：只拉头部，不会把整个
  视频读进内存。
- **▶ 提示层必须 `pointer-events: none`**。点击由容器统一处理（就地挂上 `controls`
  并 `play()`）；提示层若拦住点击，就成了「点了没反应」或双重触发。

**Blob URL 必须回收**。`io.getAsset(id, true)` 每次调用都**新建一个** URL（刻意为之：
调用方各自持有、各自释放，避免共享 URL 被谁提前 revoke）。代价是 refresh —— 切页、
附加/移除附件后重建 DOM —— 每次都会漏一批，而视频预览 + 图片缩略图一次就要两个。
侧栏没有 unmount 钩子，统一在 `render` 重建 DOM 前回收，池子挂在**侧栏实例**上
（模块级单例会被多个实例互相 revoke 掉还在用的 URL）。

## 附件元信息（文件页）

卡片与摘要行已经承担了名称 / 大小 / 时长，下面的小表格只列它们放不下的：

**文件信息**：类型 / 修改时间。
修改时间取 `File.lastModified`（本机文件的真实修改时间）；
从 XMind 包里还原出来的附件没有这个信息，退化为入库时间。

**视频元信息**：分辨率 / 帧率 / 比特率 / 视频编码 / 音频编码 / 容器。
（时长不在表里 —— 由 `fillVideoMeta` 解析完后回填给摘要行。）

这里有个坑值得记一笔：**浏览器 API 只给得出一半**。

| 字段 | 来源 |
|---|---|
| 时长 | `video.duration`（解码器实测，比容器里声明的 `mvhd` 可靠） |
| 分辨率 | 自己解容器 `stsd`（`videoWidth` 是显示尺寸，遇旋转元数据会给出旋转后的值） |
| 帧率 | 自己解容器：`stts` 总采样数 ÷ 轨道时长 |
| 视频/音频编码 | 自己解容器：`stsd` 四字符码（Web API **完全没有**对应能力） |
| 比特率 | 文件字节数 × 8 ÷ 时长（容器里声明的常不准） |

所以 `mediainfo.js` 自己实现了 MP4/MOV 的 box 树解析与 WebM 的 EBML 解析，
再与 video 元素拿到的时长互补。

几个实现上的取舍：

- **只读文件头尾各 2MB**。`moov` 常在文件尾部（非流式优化的 mp4），
  从尾部切片时起点可能落在 `mdat` 数据中间，常规 box 遍历会把它当
  `size==0`（延伸到文件尾）然后直接停下 —— 因此加了 `findMoov` 特征字节回退。
- **结果写回资产库**（`saveAssetMeta`），下次打开直接读，不重复解析。
- **容器解析优先于 video 元素**。早期版本让 video 元素无条件覆盖分辨率，
  结果非视频文件也会被填上一个凭空的分辨率。现在：容器有值用容器，
  解不出来才兜底，兜底也没有就显示 `—`，不编造。
- `Blob.arrayBuffer()` 在部分环境缺失，读文件头留了 `FileReader` 回退 ——
  否则容器解析会静默失败、元信息整片空白。

## 与 C# 版的差异说明

- **撤销/重做**：优先用编辑器自维护的历史栈 `window.editor.history`（上游 dist 页已补齐，100 步、基线模型），拿不到时回退插件层 50 步快照栈。
- **垂直对齐**：只移植 `valign`（上/中/下）。C# 另有 `Vo*` 九个滑块（3 层级 × 3 对齐的像素微调），那是临时调试脚手架，且「固化」时会用正则改写 `index.html` 源码 —— Web 沙箱无权改本地文件，故不移植。
- **搜索结果面板**：不需要插件实现。编辑器页面自带（匹配数 >3 自动弹出、可点击跳转、内容变化后自动重建），插件层只在工具栏显示「当前/总数」计数。
- **备份**：间隔可配（关闭 / 1 / 2 / 5 / 10 / 30 分钟），到点逐张比对指纹，内容没变不写盘，与 C# 版 `MaybeBackupAsync` 行为一致。
- **画布页签**：拖拽排序已实现（HTML5 drag，落点左半插前 / 右半插后，带竖条指示）。
- **导出格式**：XMind / JSON / TXT / Markdown / SVG / PNG 齐全。`.txt` 与 `.json` 同内容仅扩展名不同（对齐 C# 版）。

## 已知限制

1. **附件跨机依赖 XMind 或原文件**：`.json` 只带引用（文件名 + id），换机器后附件打不开；要连同附件迁移请导出 `.xmind`。
2. **沙箱内无法「打开」本地文件**：Web 拿不到真实路径，附件的「下载」等价于另存为。
3. **自定义图片图标**以 dataURL 内联进脑图，会显著增大文件，建议控制在 2MB 内。
4. 节点自定义图标集未移植（原项目用的是裁剪雪碧图）。
